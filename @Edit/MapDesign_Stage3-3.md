# 3-3 맵 설계 — 함정 회랑 (v1)

2026-10-12 요청 기준. 설계 코드와 배치 데이터 작성 및 수치 검증 완료. Unity 씬 적용과 플레이 검증은 미실시(MapEdit 규칙 1).

## 요청과 단위

- 플레이어 이동 동선: 설계 척도 70 = 560 월드 유닛(규칙 15, moveSpeed=8 환산).
- 움직이는 발판 5, 데미지 발판 10, 점멸 발판 10, 화살 트랩 20, 텔레포트 트랩 30.
- 일반 발판 52개(시작 1, 골인 1, 스위치 탑재 50). 총 발판 77개, 점프 76회. 함정은 발판과 별도 집계한다.
- 화살 트랩 = 기존 SwitchTrigger → ProjectileLauncher → TrapProjectile. 텔레포트 트랩 = SwitchTrigger + SwitchTeleportTrap(TrapDesign_SwitchTeleport.md), 목적지는 영역 시작점.

## 구조

오른쪽으로 진행하는 한 줄 회랑이다. 높이는 0 → 3.6 → 0 파동을 4회 반복하고, 인접 발판 높이 차는 0 또는 ±0.9다(점프 최고 높이 약 1.376 이내).

| 구간 | 발판 순서 | 내용 |
|---|---|---|
| 도입 P00~P20 | ★ + (화살 일반 → 특수) × 10 | 화살 스위치 10개, 텔레포트 없음 |
| 본 구간 P21~P75 | 텔레포트 일반 1~2개 + (화살 일반) + 특수 반복 | 텔레포트 30개 전부, 화살 10개 |
| 끝 | 텔레포트 일반 1개 → ○ P76 | |

- 특수 발판 25개는 순서대로 데미지 → 점멸 → 데미지 → 점멸 → 이동을 5회 반복한다(데미지 10, 점멸 10, 이동 5). 특수 발판끼리 인접하지 않는다.
- 일반 발판은 폭 약 4.22, 특수 발판은 폭 4.0이다. 일반 발판 폭은 이동 거리가 정확히 560이 되도록 이분법으로 계산했다. 발판 간 중립 공백은 3.2다(규칙 14: 걸어서 떨어지면 닿지 못하고 점프해야만 닿는 거리).
- 직선 구간 발판은 쪼개지 않고 긴 발판 하나로 둔다(규칙 13).

## 함정 배치

### 화살 20개 (A01~A20)

- 스위치는 일반 발판 오른쪽 끝에서 1.5 안쪽, 윗면 + 0.3. 발사 지점은 바로 다음 특수 발판 왼쪽 끝 0.3 앞, 두 윗면 중 높은 쪽 + 0.8, 왼쪽 발사.
- 3-1과 같은 값: 예고 0.5초, 쿨다운 3초, 속도 6, 수명 0.8초, 피해 8. 모든 화살 스위치 다음 발판은 특수 발판이라, 착지하기 전 위협 → 착지 후 발판 규칙 순으로 두 가지를 읽어야 한다.

### 텔레포트 30개 (T01~T30)

- 스위치는 일반 발판 중앙, 윗면 + 0.3. 폭 4.2 발판이라 가장자리에서 도약해 스위치를 넘어 착지할 수 있다(밟을지 고를 수 있음, 해당 문서 7-1·7-2).
- 첫 스위치 X는 153.6으로 경로 전체 길이(558.2)의 1/4(139.6) 뒤다(7-3). 텔레포트와 화살 스위치는 같은 발판을 쓰지 않는다(7-5).
- 쿨다운 3초, 예고 없음, 피해 0(`penaltyDamage` 기본). 목적지 = 영역 `ZoneStartPoint`.

## 특수 발판 설정

- 데미지: 3-1과 같음. 안전 2.5초 → 활성 1.5초, 첫 피해 지연 0.5초, 피해 8, 간격 0.5초. cycleOffset은 0.3초씩 증가.
- 점멸: 켜짐 2.0초, 꺼짐 1.0초, startDelay는 0.3초씩 증가(발판이 인접하지 않으므로 동기화 부담 없음).
- 이동: 중심 X ±0.4 수평 왕복(0.8 이동, 규칙 17의 56 이내), 속도 0.8, 끝점 대기 0.4초, 출발 지연 0, 0.7, 1.4, 2.1, 2.8초. 경로는 절대 상대맵 좌표라 배치 시 영역 오프셋을 더하고 PlatformPath 방식으로 변환한다.

## 수치 검증 (Generate_Stage3-3.ps1 실행 결과)

`PASS: platforms=77 (normal=52); route=560.000000000 / 70.000000000 design units; Damage=10 Blinking=10 Moving=5 Arrow=20 Teleport=30; normalWidth=4.2165; goalX=558.24; firstTeleportX=153.58`

- 경로 거리는 생성 좌표의 Σ sqrt(ΔX² + ΔY²)로 재계산, 오차 0.000001 이내. 이동 발판 중립 위치 기준이며 실제 점프·대기·회피를 포함한 이동 거리나 통과 시간을 보장하지 않는다.
- 공백(규칙 14): 중립 3.2, 이동 범위 포함 2.8~3.6. 걸어서 0.9 내려가도 수평 도달 약 2.0이라 닿지 않고, 점프 최대 수평 도달 약 3.9(+0.9 착지) 이내라 점프로만 건넌다. 플레이어 몸 폭과 실제 조작은 플레이 검증 필요.
- 개수·스위치 발판 비공유·화살 다음 발판=특수·텔레포트 첫 스위치 1/4 이후를 스크립트가 직접 검사한다.
- 데이터: 정확한 좌표는 MapDesign_Stage3-3.json, 표는 MapDesign_Stage3-3_Placement.md. 좌표는 시작점 기준 상대값이며 Y는 윗면.

## 확인이 필요한 사항

1. **텔레포트 30개는 권장 초과**: TrapDesign_SwitchTeleport.md 7-4는 영역당 2개 이내를 권장한다. 요청대로 30개를 배치했지만 후반부에서 밟으면 시작점으로 돌아가는 영역이라 난도가 매우 높다. 스위치를 넘기 어렵다면 일반 발판 폭 확대(공백과 맞바꿈)나 `penaltyDamage`/시작점 대신 `customDestination`(구간 중간 체크포인트) 사용을 검토할 것.
2. 영역 크기: 영역 폭은 약 -10 ~ 568, Y -8 ~ 12다. 현재 Stage3의 3-3 영역(x 169~211)보다 크게 넓어 3-4 이후를 오른쪽으로 옮기고 카메라 영역·`OutOfBoundsTrigger_3-3_3-4`·3-2 층 사이 추락 판정을 다시 맞춰야 한다(규칙 12, 16, 19). 적용 시 규칙 16에 따라 위치를 조정한다.
3. "움직이는 발판"을 `MovingPlatform` 수평 왕복으로 해석했다. 3-2처럼 수직 이동을 원하면 알려달라.
4. 일반 발판 52개는 스위치 탑재와 시작·골인용이다. 모두 지정 종류(예: 소멸 발판)로 바꿔야 하면 알려달라.
