# 플레이어 방어 설계 — 컨셉

- 우클릭을 누르는 동안 일반 방어: 들어오는 공격 피해 전부 차단. 방향 제한/스태미나 비용 없음.
- 입력 프레임 F, F+1, F+2의 적중은 완벽 방어. F+3부터 일반 방어. 렌더 프레임 기준이므로 FPS에 따라 실제 시간은 달라짐.
- 완벽 방어: 5초 동안 장비 포함 공격력 20% 증가(정수 반올림), 방어한 원래 공격 피해의 50%를 임시 체력으로 생성.
- 반복 획득은 중첩 없이 공격력 유지, 5초 재시작, 임시 체력은 새 공격 피해의 절반으로 교체.
- 방어하지 못한 피해는 기존 방어력 경감 후 임시 체력부터 차감. 임시 체력은 소수 보존, 남은 실제 체력 피해는 정수 올림.
- 일반 방어는 버프를 주지 않음. 버프 만료/컴포넌트 비활성화/무장해제 시 제거. 무장해제 중 방어 불가.
- 우클릭은 방어, 좌클릭은 기존 검 공격을 유지한다. 우클릭 특수 액션과의 입력 중복은 향후 적용 시 해소한다.
- 기존 PlayerHealth.TakeDamage 경로에 통합하여 보스/적/투사체에 적용. 현재 같은 경로의 환경 피해도 차단 가능.

## 미디어 연결

PlayerSpriteAnimator의 Guard Right Frames / Guard Left Frames에 VARCO로 생성한 방향별 모션을 Unity Sprite 프레임으로 변환하여 순서대로 할당한다. Guard Frames Per Second, Guard Visual Offset Y로 속도와 발 위치 보정. 미할당 시 대기 포즈를 사용한다.
PlayerDefenseFeedback의 Guard Start Sfx / Normal Block Sfx / Perfect Block Sfx에 AudioClip을 할당한다. 미할당 시 무음.
추가 이펙트/별도 Animator/버프 UI는 PlayerDefense.OnGuardChanged(bool), OnBlocked(bool: 완벽 여부), OnBuffChanged(float: 임시 체력, float: 남은 초)에 구독한다. 남은 시간 연속 표시는 BuffRemaining을 조회한다.
향후 본 게임 적용 승인 후 플레이어 원본 Prefab에 PlayerDefense와 PlayerDefenseFeedback을 연결한다. 새 스크립트는 Assets/@Scripts/Player에 저장한다. 런타임에 컴포넌트를 자동 추가하지 않는다.

## 확인 시나리오

1. 우클릭 없이 피격: 기존 체력 감소/무적 시간 유지.
2. 입력 프레임과 다음 2프레임 피격: 체력 감소 없음, 공격력 1.2배, 피해 30이면 임시 체력 15.
3. 입력 3프레임 후 피격: 일반 방어, 버프 없음.
4. 우클릭 해제 후 피격: 방어력 경감 후 임시 체력을 먼저 소비.
5. 5초 후 공격력 원복/임시 체력 제거. 중간 장비 변경에도 20% 유지.
6. 연속 완벽 방어: 지속시간 재시작, 임시 체력 교체, 공격력 중첩 없음.
7. 애니메이션/사운드 미할당 상태와 할당 상태 양쪽 확인.

## 제안 기본값과 적용 전 결정사항

요청에 명시되지 않은 일반 방어의 피해 전부 차단, 누르기 유지, 재획득 교체, 방향 제한 없음, 무장해제 시 방어 불가는 컨셉 기본안이다. 기존 입력 변경 기록에 따라 우클릭 방어와 좌클릭 검 공격을 유지한다. 환경 피해 방어 여부는 공격 정보 확장 시 별도로 구분해야 한다.

VARCO 결과가 3D 리깅 애니메이션이면 이 2D 게임의 방향별 스프라이트로 렌더링해 사용하거나 별도 Animator 어댑터가 필요하다. 현재는 생성 요청 없이 프레임 슬롯과 이벤트만 설계했다. 방어 진입 모션, 유지 모션, 일반 성공 및 완벽 성공 별도 연출은 OnGuardChanged와 OnBlocked로 연결할 수 있다.

구현 초안은 PlayerDefenseConcept/@Scripts에 보관했다. 기존 4개 클래스 파일은 통합 참고용이며 통째로 덮어쓰지 않는다. IntegrationDraft.patch는 중단 당시 변경 기록이므로 최종 적용 패치가 아니다.

## 방어 성공 시 몬스터 넉백

일반 방어와 완벽 방어 모두 성공한 순간, 해당 공격을 가한 몬스터를 플레이어에게서 멀어지는 방향으로 밀어낸다. 넉백 자체는 추가 피해를 주지 않는다. 완벽 방어의 5초 공격력 증가와 임시 체력 효과는 그대로 유지한다.

### 판정과 방향

- 방어에 성공한 실제 공격 1회당 공격한 몬스터에게 넉백을 1회 적용한다. 버튼 입력만으로는 발생하지 않는다.
- 공격 정보를 통해 전달받은 공격자만 대상으로 삼는다. 근처의 다른 몬스터를 검색하거나 범위 전체를 밀지 않는다.
- 횡스크롤 기준 수평 넉백을 사용한다. 몬스터가 플레이어 오른쪽이면 오른쪽, 왼쪽이면 왼쪽으로 밀고 기존 수직 속도와 중력은 유지한다. 같은 X좌표라면 공격 진입 방향의 반대쪽, 해당 정보도 없으면 플레이어가 바라보는 방향으로 민다.
- 일반 방어와 완벽 방어는 동일한 넉백을 기본으로 한다. 추후 밸런스 조절을 위해 두 강도와 지속시간은 각각 설정할 수 있게 분리한다. 구체 수치는 적용 단계에서 정한다.
- 벽 등 지형 충돌을 존중하며 순간이동이나 벽 관통을 사용하지 않는다. 사망·제거된 공격자는 무시한다.

### 공격 정보와 컴포넌트 연동

현재 `TakeDamage(int)` / `TryBlock(int)`만으로는 공격자가 누구인지 알 수 없다. 넉백을 적용할 경로에는 공격자 참조, 공격 진입 방향, 공격 1회 식별자를 포함한 공격 정보를 추가한다. 기존 정수 피해 경로는 호환을 위해 유지하되 공격자를 추측하지 않는다. 공격자 정보가 없으면 피해 차단과 기존 버프만 처리하고 넉백은 생략한다.

1. 몬스터 근접 공격 또는 투사체 생성 시 원래 공격자와 공격 식별자를 기록한다. 하나의 공격이 여러 콜라이더에 닿아도 동일한 식별자를 사용한다.
2. 플레이어 체력 처리에서 방어 판정으로 공격 정보를 전달한다. 방어 성공 시 기존 `OnBlocked(bool)`와 별도로 공격자·공격 식별자·완벽 방어 여부·넉백 방향을 담은 `OnBlockSucceeded` 이벤트를 발행한다. 기존 사운드 구독은 유지한다.
3. 별도 방어 반응 처리기가 이벤트를 받아 공격자의 넉백 수신 컴포넌트에 요청한다. 공격 식별자별 중복 처리는 피해 판정 계층에서 막아 넉백과 완벽 방어 버프가 여러 번 발생하지 않게 한다.
4. 몬스터 넉백 컴포넌트가 물리 이동을 담당한다. 넉백 유지 중에는 AI의 수평 이동 갱신이 넉백을 덮어쓰지 않도록 이동 제어권을 잠시 전환하고, 종료 후 생존한 몬스터의 기존 AI 이동을 재개한다. 중간에 새 공격을 방어하면 속도를 무한 누적하지 않고 새 넉백으로 갱신한다.

투사체 공격을 막았을 때는 투사체 자체가 아니라 기록된 원래 공격자를 밀어낸다. 원래 공격자가 이미 제거되었거나 넉백 수신 기능이 없으면 넉백만 생략하며 방어 성공은 유지한다. 환경 피해처럼 몬스터 공격자가 없는 경우도 같다. 보스는 별도 면역을 기본으로 두지 않고 같은 규칙을 적용하며, 필요하다면 개별 넉백 저항을 후속 밸런스 항목으로 설계한다.

### 연출 연결과 검증 항목

VARCO 방어 모션과 사운드가 없어도 방어 성공 및 넉백 판정은 진행한다. 몬스터 밀림 모션·효과음은 넉백 시작/종료 이벤트로 나중에 연결한다. 실제 넉백은 애니메이션 이벤트나 클립 길이에 의존하지 않는다.

- 일반 방어 성공: 체력 감소 없이 공격자만 밀리고 완벽 방어 버프는 새로 생성되지 않는다.
- 완벽 방어 성공: 공격자 넉백과 기존 5초 버프가 함께 발생한다.
- 좌우 및 같은 X좌표의 공격에서 방향 계산이 일관되는지 확인한다.
- 다중 콜라이더와 지속 접촉에서도 한 공격당 넉백이 한 번만 발생하는지 확인한다.
- 투사체는 원래 공격자에게 적용하며, 공격자 정보 누락·공격자 제거 시 오류 없이 방어를 유지한다.
- 넉백 중 AI가 이동을 덮어쓰지 않고, 벽 앞에서 관통하지 않으며, 종료 시 AI가 정상 재개되는지 확인한다.

이번 수정은 설계 문서에 반영했다. `PlayerDefenseConcept/@Scripts`와 `IntegrationDraft.patch`는 공격자 정보 및 넉백이 연결되지 않은 이전 구현 참고 자료다. 본 게임 적용 시 위 공격 정보와 넉백 경로를 추가해야 한다. Unity 조작 및 본 게임 파일 변경은 수행하지 않았다.

## 완벽 방어 이펙트 (설계)

현황: 방패 앞 3프레임 이펙트(번쩍임 → 링 → 불꽃, 15fps, 0.2초)가 `PlayerDefenseFeedback`과 `Player_Warrior.prefab`에 연결돼 있으나 플레이 모드 확인은 하지 않았다. 아래는 "완벽 방어가 눈에 확실히 보이게" 하기 위한 설계이며 아직 Unity에 적용하지 않았다.

### 단계별 연출
1. **순간 이펙트(0.2~0.3초)**: 완벽 방어 성공 순간 기존 3프레임을 방패 앞이 아닌 **공격이 닿은 지점**에 재생한다. 접점은 공격자 몸과 플레이어 사이 중간 X, 플레이어 몸통 높이를 사용하고 공격자 정보가 없으면 현재 방패 위치로 대체한다. 일반 방어에는 재생하지 않는다.
2. **크기/가독성**: 일반 방어와 확실히 구분되도록 플레이어 몸집의 약 1.5배, 밝은 금색 계열, 마지막 프레임에서 페이드아웃한다. 스프라이트 정렬은 플레이어보다 위로 한다.
3. **버프 유지 표시(5초)**: 공격력 +20% 동안 플레이어에게 옅은 금색 오라 또는 검 반짝임을 표시한다. `OnBuffChanged`로 시작/갱신, 남은 시간이 1초 이하이면 깜빡이고 만료/해제/무장해제 시 즉시 끈다. 재획득 시 중첩 없이 시간만 재시작한다.
4. **히트 피드백(선택)**: 0.05초 히트스톱과 약한 카메라 흔들림. 스피디 플랫포머 테마상 정지 시간은 0.05초를 넘기지 않는다. 기본값은 끔으로 두고 인스펙터에서 켠다.

### 구현 방침
- 순간 이펙트는 `OnBlocked(true)` 대신 위치 정보가 있는 `OnBlockSucceeded(공격자, 완벽 여부, 방향)`을 구독하고, 이 이벤트가 없는 경로는 기존 `OnBlocked`로 대체한다.
- 오라는 `PlayerDefenseFeedback`에 필드를 추가하거나 별도 자식 오브젝트로 두며, 런타임 자동 추가는 하지 않는다. 새 스크립트는 `Assets/@Scripts/Player`에 둔다.
- 이미지는 기존 이펙트 3장을 재사용하고, 오라/접점용 추가 이미지는 VARCO로 생성한다(색 히트박스 대신 이미지 사용).
- 효과음은 이펙트 시작과 동시에 재생한다. 이펙트 이미지가 없어도 판정과 버프는 정상 진행한다.

### 확인 항목
- 완벽 방어 시 이펙트가 보이는지, 일반 방어에서는 나오지 않는지 확인한다.
- 좌우 방향과 같은 X 좌표의 공격에서 접점 위치가 맞는지 확인한다.
- 연속 완벽 방어에서 이펙트가 겹쳐 쌓이지 않고 오라 시간만 재시작되는지 확인한다.
- 5초 후/무장해제/비활성화 시 오라가 남지 않는지 확인한다.
- 보스 공격에서 공격자 정보가 없을 때 방패 앞 위치로 대체되는지 확인한다.
