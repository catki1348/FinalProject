# LHS_Custumer.md — Work Rules

Rules for how work in this project must be carried out. All entries are kept in English (rule 2).

1. Any response discussing or reviewing these rules must be given in Korean.
2. Any rule submitted in a language other than English must be simplified and stored here in English.
3. Rules are prioritized in ascending order by number — a lower rule number takes precedence over a higher one.
4. Unless an explicit exception is stated for a task, all work must follow these rules.
5. If two or more rules conflict, ask the user how to resolve it before proceeding.
6. Review these rules before starting any task. After finishing, check the resulting work against these rules; if no violation is found, the task is complete.
7. When asked to add a new rule: if no position is specified, append it at the bottom with the next number. If the user specifies a number, insert it there and shift the existing rule at that number and all after it down by one.
8. When generating an image in a workflow, enter text specifying that it be generated at 4K resolution.
9. Any work that uses Unity is carried out only after asking the user and receiving an answer. This includes all work that uses Unity in any way, such as saving or moving any object into Unity.
10. A rule prefixed with `_Unity /` applies only to work done in the Unity program; skip it when reviewing work done in any other program.
11. Do not perform any work through Unity unless explicitly instructed to work in Unity.
12. A rule prefixed with `_Blender /` applies only to work done in the Blender program; skip it when reviewing work done in any other program.
13. When working with a workflow, do not use the "Run All" action, but run the created nodes simultaneously so the work itself is processed in parallel.
14. When downloading a 3D model from VARCO, download static (non-animated) models as GLB.
15. `_Blender /` When doing work in Blender that adds something to a character, preserve the original shape of each character's model as the top priority.
16. `_Blender /` When merging a character and an animation in Blender, make sure the character's rigging and the animation's rigging match 1:1.
17. `_Blender /` When merging an animation and a character, make sure the skeleton does not stick out beyond the character (no bones visibly exposed outside the mesh).
18. When asked to generate an image or 3D model, use the connected workflow to generate it. If generation is not possible or no workflow is connected, ask the user to connect a workflow instead.
19. Name a 3D model generated by a workflow using core keywords from the text used to generate it, so the name intuitively conveys its content.
20. `_Unity /` When bringing a 3D model generated by a workflow into Unity, do not register it directly in the scene. Make it a Prefab and register it only in the `@Prefab` folder.
21. If a failure occurs during a multi-node workflow run, proceed with the other, non-failed nodes individually.
22. When a screenshot is used to check work status, delete the screenshot file completely after confirming the work, so it does not take up storage space.
23. `_Unity /` Unless otherwise requested, save Prefab files only in `@Prefab`.
24. `_Unity /` When testing is needed in Unity, create a temporary scene named like `Test000`, `Test001`, `Test002`, etc., test in it, and delete that scene once testing is finished. This rule always applies unless otherwise requested. If a scene with the same name as the test scene to be created already exists, create a new scene with a different name to test instead.
25. If a situation arises that is not covered by any rule defined here, refer to `CLAUDE.md`.
26. In a workflow, before starting work, delete any node that has been unused for over 1 hour, except nodes that are currently waiting to be used.
27. If a node exists that is not currently in use, reuse that node.
28. When asked to organize/manage a set of items, create a folder named `@[management-target-name]` for them, and save the items inside it in folders named `[management-target-name]_[number]`. Create management folders under the relevant program's folder inside `C:\Users\MBC-501-16\Downloads\LHS`. If `C:\Users\MBC-501-16\Downloads\LHS` does not exist, work in `C:\Users\catkl\OneDrive\문서\LHS` instead.
29. When checking the completeness of a finished result, take 5 screenshots — front, back, left, right, and top (overhead) views — to verify it.
30. When asked to generate a Preview, bring the 3D model into Blender, take 5 shots — front, back, left, right, and top (vertical) views — and combine them into a single image. The 5 images must not overlap each other. Except for the center image, the other 4 images must be placed to fit exactly into each corner of a square. Name the resulting image file using keywords from the 3D object it depicts.
31. When multiple tasks started at the same time progress at different speeds, do not try to keep their progress in sync — proceed first with whichever tasks can move faster.
32. When the command `LHS_UpLoad` is received, copy the `@Screenshots` folder to `C:\Users\MBC-501-16\Documents\Project.NewEra\Project.NewEra\Assets\Screenshots`. When creating a folder, include its creation date in the folder name. Folders created before today are not copied even when the `LHS_UpLoad` command is received.
33. For a work item that has been marked as discarded, delete the completed work item and do not regenerate it until a separate instruction is given for that work. For a 3D object, also delete its image-generation and 3D-model-generation nodes.
34. When asked to generate a 4-view orthographic turnaround (front/back/left/right), do not combine the 4 views into a single image — generate each view as its own separate image.
35. When generating a 3D model for a subject that has a 4-view turnaround, generate the 3D model by referencing that subject's 4-view images.
36. When a 3D object has been generated, compare its silhouette against the original's silhouette. Report failure if the match rate is below 90%, and report success if it is 90% or above.
37. When a task fails, analyze the cause of the failure and report an improvement plan for it.
38. When a Preview has been generated, copy the Unity Prefab file with the same name as the screenshot file, and save the copy in the same location as the screenshot file. Also copy every file that makes up the Prefab (such as its `.glb`) along with it.
39. `_Unity /` Architecture & Manager: Use dedicated Manager classes to centrally control common systems such as state, sound, and UI. Restrict singleton usage to Manager classes only (e.g. `GameManager.Instance`); never use singletons for regular objects such as the player or monsters. Follow the Single Responsibility Principle — one script, one role (e.g. split a Player script into Movement, Health, and Inventory scripts).
40. `_Unity /` Object Communication: Strictly forbid `GameObject.Find()`; reference objects via Inspector assignment (drag & drop) or Manager caching instead. Use event-based communication (Observer pattern) via C# `event`/`Action` to minimize coupling (e.g. Player only raises a "hit" event, and UI subscribes to it to update itself).
41. `_Unity /` Object References: Except in special cases, prefer `GetComponent`-family functions over direct Inspector assignment. Strictly forbid hierarchy-search functions such as `GameObject.Find` to avoid runtime performance loss. Avoid comparisons using strings (tags, names, etc.) to prevent performance loss and human error.
42. `_Unity /` Resources & Assets: Prioritize Prefabs — any dynamic or repeated object must be made into a Prefab; do not edit such objects directly in the scene, always edit the original in Prefab Mode. Use prefix naming rules for intuitive asset identification (e.g. `P_` for Prefab, `T_` for Texture, `M_` for Material). Place prefabs in per-category folders under the `@Resources` folder so the user can easily swap prefabs.
43. `_Unity /` Except in special cases, do not perform dynamic object allocation in code that runs every frame, such as in `Update`.
44. When finishing any piece of work, write comments that explain what each function/feature does, so the user can pick it up and code by hand later without needing to ask.
45. `_Unity /` When any file inside `Assets` exceeds 10MB, move it into the `@ExternalAssets` folder and update every reference/path pointing to it so nothing breaks.
46. `_Unity /` Store `.md` files inside an `@Edit` folder created within the project.
47. When the command `/프로젝트 체크` is received, perform the Project.md recording task for every session in the relevant group.
48. `_Unity /` Save any script that is created inside the `@Scripts` folder.
