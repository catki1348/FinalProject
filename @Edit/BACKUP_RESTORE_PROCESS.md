# /BackUpOn — 백업 복원 후 작업 재개

사용자가 `/BackUpOn`을 입력하면 백업된 파일을 복원하고, 복원된 세션에서 마지막으로 중단된 작업을 이어서 진행한다.

## 절차

1. `LHS_Custumer.md`를 확인한다. 백업·복원 절차는 `G:\내 드라이브\LHS`의 최신 문서를 우선해서 읽고 적용한다. `LHS_Home`은 읽거나 복원 기준으로 사용하지 않는다. 해당 경로에 접근할 수 없으면 이를 알리고 로컬 문서를 대체 기준으로 사용했음을 명시한다.
2. 명령어와 함께 백업 경로가 제공되면 해당 파일을 사용한다. 경로가 없으면 최신 문서의 `LHS_ROOT` 결정 규칙으로 저장 위치를 찾고 백업 목록을 확인한다. 복원 대상이 하나면 사용하고, 여러 개면 생성 시각·포함 세션을 제시하여 사용자가 선택하도록 한다. 수정 시각만으로 대상 백업을 단정하지 않는다.
3. 백업의 매니페스트, 포함 파일, 원본 앱, 복원 경로를 확인하고 무결성을 검증한다. 현재 문서는 Claude의 `.claude` 세션 백업을 설명한다. Codex 백업으로 간주하거나 Codex 저장소에 복사하지 않는다. Unity 프로젝트·외부 리소스는 백업에 포함된 것으로 가정하지 않는다.
4. 최신 문서가 지정한 복원 스크립트를 찾아 내용을 확인하고, 지원되는 경우 `-DryRun`으로 복원 계획을 점검한다. 기존 복원 대상 파일은 별도로 보존한 뒤 복원한다. 압축 내부 경로가 복원 대상 폴더 밖으로 나가지 않는지 확인한다. 스크립트가 없거나 백업이 손상되었으면 복원 완료로 보고하지 말고 원인과 필요한 조치를 알린다.
5. 백업 데이터의 프로젝트 경로를 현재 PC의 실제 작업 경로에 맞춰 매핑하고 복원한다. 사용자 지정 경로가 있으면 우선 적용한다. 실행 중인 앱이 기록 중인 세션 파일과 충돌하면 해당 세션을 안전하게 닫은 뒤 진행한다.
6. 복원 후 파일 누락과 매니페스트 해시를 확인한다. 복원 결과와 사용한 백업 경로를 보고한다. 앱 재시작이나 세션 재열기가 필요하면 안내하며, 실제로 열리지 않은 세션을 활성화되었다고 보고하지 않는다.
7. 복원된 대화 기록과 인계 문서를 읽어 마지막 사용자 지시, 완료된 작업, 남은 작업을 파악한다. 현재 작업 파일 상태와 대조하여 완료된 작업을 반복하지 않고 미완료 작업을 이어서 진행한다. 이어갈 작업이 여러 개로 불명확하면 선택을 요청한다.

이 문서는 명령 실행 절차를 정의한다. 명령어 등록 자체로 복원을 실행하지 않는다. 외부 경로 접근에 필요한 실행 환경의 권한 절차는 준수한다.
