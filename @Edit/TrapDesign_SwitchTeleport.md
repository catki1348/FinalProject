# 스위치 연동 텔레포트 함정 설계안

> 이 문서는 설계만 다룹니다. 스크립트 작성, 씬 오브젝트·프리팹 배치 등 Unity 작업은 `LHS_Custumer.md` 규칙 9, 11에 따라 사용자 승인 후 별도로 진행합니다.
> 기반 문서: `TrapDesign_SwitchZoneMonster.md`(개정 2판, 13항 구현 현황). 이 문서는 그 6항(구간 진입 텔레포트)의 **발동 방식만 확장**합니다.

## 1. 요구사항

1. 텔레포트 트랩은 **맵에 배치된 스위치 트랩(`SwitchTrigger`)을 밟으면 작동**한다. 별도의 발동 영역 박스를 두지 않는다.
2. 효과는 별도로 지정하지 않으면 **플레이어를 시작점으로 날려버린다**(진행 상황을 잃는 벌칙형).
3. 효과를 별도로 지정하는 설계(예: 지정 지점 이동)는 같은 컴포넌트의 목적지 필드만 바꿔서 지원한다.

## 2. 기존 구조와 달라지는 점

| 항목 | 기존 `TeleportTrap`(구간 진입형) | 신규 `SwitchTeleportTrap`(스위치형) |
|---|---|---|
| 발동 | 자기 트리거 영역에 플레이어 진입 | 연결된 `SwitchTrigger.OnActivated` 구독 |
| 반복 | `oneShot`/`retriggerCooldown` | 스위치의 `oneShot`/`cooldown`을 그대로 사용(중복 로직 없음) |
| 목적지 | `destination` 필수 | 기본 = **시작점**, 지정 시 그 지점 |
| 콜라이더 | 필요(발동 영역) | 불필요(스위치가 감지) |

기존 `TeleportTrap`과 3-4의 텔레포트 5개(낙하 포착형)는 **수정하지 않습니다.**
스위치의 발동 감지는 이미 `SwitchTrigger`가 하므로 새 컴포넌트는 "누가 밟았는가 → 어디로 보낼 것인가"만 담당합니다(규칙 35).

## 3. 시작점의 정의

기본 목적지는 **플레이어가 해당 영역(Zone)에 처음 들어올 때 서는 지점**, 곧 그 영역의 `ZoneStartPoint`입니다.
`StageManager.MovePlayerToStartOfCurrentArea`가 사망 후 재시작과 영역 진입에 같은 지점을 사용하므로 기준이 일치합니다.

- 인스펙터에 `ZoneStartPoint startPoint`를 연결(`Find` 금지, 규칙 36).
- 별도 지정이 필요하면 `Transform customDestination`을 채운다. 값이 있으면 `startPoint`보다 우선한다.
- 3-1 등 신규 영역은 영역마다 `ZoneStartPoint`가 이미 있으므로 새 오브젝트가 필요 없다.

## 4. 스위치 이벤트 확장 (기존 파일 수정 1건)

현재 `SwitchTrigger.OnActivated`는 인자가 없어서, 누가 밟았는지(= 보낼 플레이어)를 알 수 없습니다.
기존 `ProjectileLauncher`를 건드리지 않기 위해 **이벤트를 하나 추가**합니다(기존 이벤트와 동작은 그대로).

```csharp
// SwitchTrigger.cs — 추가분
// 스위치를 밟은 플레이어의 Rigidbody2D를 함께 전달(텔레포트 등 플레이어에게 작용하는 함정용)
public event Action<Rigidbody2D> OnActivatedByPlayer;

// OnTriggerEnter2D 안, 기존 OnActivated?.Invoke(); 바로 아래
OnActivatedByPlayer?.Invoke(body);
```

## 5. 신규 스크립트: `SwitchTeleportTrap`

위치: `Assets/@Scripts/Trap/SwitchTeleportTrap.cs`

```csharp
// SwitchTrigger를 밟은 플레이어를 영역 시작점(또는 지정 지점)으로 날려버리는 함정. 예고 없이 즉시 발동한다.
// 이동 방식은 TeleportTrap과 같다(rb.position 직접 이동 + 속도 초기화 + 카메라 즉시 이동).
public class SwitchTeleportTrap : MonoBehaviour
{
    [SerializeField] private SwitchTrigger switchTrigger;       // 이 함정을 발동시키는 스위치
    [SerializeField] private ZoneStartPoint startPoint;         // 기본 목적지(각 영역의 시작점)
    [SerializeField] private Transform customDestination;       // 지정 시 startPoint보다 우선
    [SerializeField] private CameraBoundsZone destinationZone;  // 목적지가 속한 카메라 구간
    [SerializeField] private PlayerCameraFollow cameraFollow;
    [SerializeField] private int penaltyDamage = 0;             // 0이면 피해 없음, 필요 시 인스펙터에서 조절
    [SerializeField] private AudioClip teleportSfx;
}
```

핵심 동작:
1. 스위치 접촉 → `OnActivatedByPlayer(body)` 수신 → **예고 없이 즉시** 이동.
2. `body.position = Destination`, `linearVelocity = 0`, `cameraFollow.SnapTo(Destination, destinationZone)`.
3. 스위치 쿨다운이 재발동을 막으므로 별도 루프 방지 코드가 필요 없다.
4. 한 스위치에 투사체 발사기와 텔레포트를 **함께** 연결할 수 있다(이벤트 멀티캐스트).

## 6. 설계 결정과 근거

| 결정 | 이유 |
|---|---|
| 기존 `TeleportTrap` 비수정, 신규 클래스 | 3-4에 이미 5개가 배치·검증되어 있어 회귀 위험을 피함 |
| 쿨다운·1회성은 스위치에 위임 | 같은 기능을 두 곳에 두지 않기 위함(SRP, 규칙 35) |
| 예고 없음 | 사용자 확정(즉시 발동) |
| 벌칙 피해 기본 0 | `[SerializeField] penaltyDamage`로 함정마다 조절(사용자 확정) |
| 목적지는 `ZoneStartPoint` | 사망/영역 진입 시 시작 위치와 일치해 플레이어가 예측 가능 |
| 스위치 외형 구분 | 투사체 스위치(노랑)와 구분되도록 텔레포트 스위치는 별도 색(자홍) 프리팹 사용을 권장 |

## 7. 맵 배치 규칙

1. 텔레포트 스위치는 **우회 불가능한 곳이 아니라 "밟을지 말지 고를 수 있는 곳"**에 둔다. 동선 중앙 발판 한가운데에 두면 회피 수단이 없어 불합리하다.
2. 스위치는 발판 위 서는 면 + 0.7(기존 스위치와 동일), 발판 끝에서 1.5유닛 이상 안쪽, 정상 동선에서 점프로 넘을 수 있는 위치.
3. 시작점과 가까운 앞부분(첫 1/4)에는 배치하지 않는다. 날려 보내도 손실이 거의 없어 함정이 의미를 잃는다.
4. 동일 영역에서 텔레포트 스위치는 **영역당 2개 이내**를 권장(과하면 진행 불가능에 가까워짐).
5. 투사체 스위치와 같은 발판에 두지 않는다(회피 동작이 겹쳐 불가피한 피해가 됨).
6. 텔레포트 스위치 주변 2유닛 안에는 몬스터 활동 영역을 두지 않는다(몬스터에 밀려 의도치 않게 밟히는 것을 방지).

## 9. 검증 체크리스트 (규칙 24: 임시 테스트 씬에서 수행 후 정리)

- [ ] 스위치 접촉 → 즉시 시작점으로 이동, 낙하/점프 속도가 0으로 초기화된다.
- [ ] 카메라가 보간 없이 시작 영역으로 즉시 이동한다(렌더 프레임 단위 확인).
- [ ] 쿨다운 3초 동안 같은 스위치 재접촉은 무시된다. 스위치가 시작점 근처여도 루프가 없다.
- [ ] 쿨다운 중 재접촉이 이중 이동을 일으키지 않는다.
- [ ] 이동형 발판 탑승 중 발동해도 부모/`riders`가 정리된다(3-4 문서에서도 미확인 항목).
- [ ] `customDestination` 지정 시 시작점 대신 그 위치로 이동한다.
- [ ] 한 스위치에 발사기와 텔레포트를 함께 연결했을 때 둘 다 동작한다.
- [ ] 기존 투사체 함정과 3-4 텔레포트 5개의 동작이 변하지 않는다.
- [ ] 무적 시간·체력 0 상태·대시 중 발동 시 비정상 동작이 없다.

## 10. 확정 사항 (사용자 답변)

1. 시작점은 **각 영역의 시작점**(`ZoneStartPoint`).
2. 맵별 설치 수량은 **설계 시 사용자가 지정**한다(이 문서는 수량을 정하지 않음).
3. **예고 없이** 발동한다.
4. 피해는 기본 0이며 `penaltyDamage`(`SerializeField`)로 조절한다.

## 13. 설계 변경 — 자체 작동형 텔레포트 발판 (2026-10-14)

### 13-1. 변경 요구와 이유

- 기존(1항): 텔레포트는 "맵에 배치된 스위치 트랩을 밟으면" 작동 → 현재 3-3은 **스위치 판 + 옆의 룬 장식** 2개로 보이고, 밟는 곳(판)과 텔레포트 표시(룬)가 따로 놀았다.
- 변경: **텔레포트 함정은 별도 스위치 발판 없이, 마법진 자체가 발판으로 작동한다.** 플레이어가 마법진 위를 밟으면 그 자리에서 작동한다.
- 효과(시작점으로 날려버림, 예고 없음, 피해 기본 0)는 그대로다. 바뀌는 것은 **발동 장치의 구성과 외형**뿐이다.

### 13-2. 구성 변화

| 항목 | 기존 | 변경 |
|---|---|---|
| 눈에 보이는 외형 | 스위치 판(`ThemedVisual`) + 1.6유닛 옆의 룬(`TeleportRune`) | **마법진 1개**(`Pad`)가 감지 위치 중앙에 놓임 |
| 밟는 위치 | 스위치 판 | 마법진 위 |
| 감지 영역 | 1.1(~1.26) × 0.18 | 마법진 폭의 90% × 0.18(최소 1.1) |
| 스크립트 | `SwitchTrigger` + `SwitchTeleportTrap` + `SwitchPressAnimation` | **동일**(스크립트 변경 없음, 눈에 보이는 스위치만 없앰) |
| 작동 연출 | 판이 눌림 + 룬이 부풀기 | **마법진이 눌리고 빛이 강해짐**(`pressFrames`) + 부풀기 |
| 배치 좌표 | 스위치 판 중심 | **기존 스위치 판 중심과 같은 X, 같은 발판 윗면** |

- 마법진의 기준점은 발판 윗면(떠 있는 간격 0), 하단 약 0.02 매립, `sortingOrder` -1(스위치 판과 같은 방식, `TrapDesign_SwitchIntegration.md` 3-1항).
- 마법진은 지나갈 때 걸리는 구조물이 아니라 **트리거**(충돌 없음)라서 걸어서 통과하며 밟힌다.
- 스위치 투사체 판과는 같은 발판에 두지 않는다(수칙 11 유지).

### 13-3. 프리팹 변경 (승인 후)

`P_Trap_Teleport_*`(스테이지별 5개, 이름 유지로 씬 참조 보존)

- `ThemedVisual`(스위치 판) 제거.
- `TeleportRune` → `Pad`로 이름 변경, 위치 (0, -0.02), 크기 1, `sortingOrder` -1.
- `SwitchPressAnimation`: `visual`·`tintTarget`·`pulseTarget`을 모두 `Pad`로 연결, `pressDepth` ≈ 마법진 높이의 30%, `pressFrames` = 충전·발동 프레임.
- `BoxCollider2D`: 폭 = `max(1.1, 마법진 폭 × 0.9)`, 높이 0.18, 오프셋 (0, 0.09).

### 13-6. 검증 체크리스트 (임시 씬)

- [ ] 마법진 위를 걸어 지나가면 밟은 위치에서 바로 시작점으로 이동한다(예고 없음).
- [ ] 쿨다운 3초 동안 같은 마법진 재접촉은 무시된다.
- [ ] 이동 직후 마법진이 눌리고 빛이 강해졌다가 쿨다운이 끝나면 복귀한다.
- [ ] 감지 영역이 마법진 폭과 맞는다(마법진 가장자리 밖에서는 작동하지 않음).
- [ ] 마법진이 발판 윗면에 틈 없이 놓이고 이동·몬스터 동선에 걸리지 않는다.
- [ ] 3-4 낙하 포착 5개의 동작이 변하지 않는다.

### 13-7. 확정 사항 (사용자 답변)

1. 마법진 작동 프레임(충전·발동) 생성 허용 → 스테이지별 2장씩 10장 생성.
2. **시작 지점으로 이동한 뒤, 효과가 플레이어 주변에 나타나도록 한다**(13-8항). 이동 전 지연은 두지 않는다(즉시 이동 유지).
3. 프리팹·씬·스크립트 변경은 Unity 작업이므로 적용 승인 후 진행한다.

### 13-8. 도착 이펙트 설계 — 이동 후 플레이어 주변에 나타나는 효과

**동작 순서** (`SwitchTeleportTrap`, 한 프레임 안)
1. 플레이어를 시작점으로 이동 + 속도 0 + 카메라 즉시 이동(기존 그대로).
2. **도착 이펙트 생성**: 이동한 플레이어 위치(발 위치)에 이펙트를 만들고 약 0.4초 동안 플레이어를 따라가게 한다.
3. 효과음(`teleportSfx`) 재생, 필요 시 벌칙 피해(`penaltyDamage`).
4. 출발한 마법진은 눌림 + 빛 강화 연출(작동 프레임)을 재생한다.

**이펙트 구성** (스테이지별 빛 색은 마법진과 동일)

| 요소 | 내용 | 시간 |
|---|---|---|
| 바닥 파문 | 마법진 스프라이트를 발 위치 바닥에 깔고 0.6배 → 1.6배로 퍼지며 사라짐(플레이어 뒤쪽 정렬) | 0.5초 |
| 에너지 입자 | 마법진 색의 작은 정사각 픽셀 입자 24개가 플레이어 몸(높이 0 ~ 1.3) 주위에서 바깥·위쪽으로 퍼지고 중력으로 서서히 가라앉으며 소멸(월드 좌표 시뮬레이션, 플레이어 앞쪽 정렬) | 0.5 ~ 0.8초 |
| 빛 기둥(선택) | 플레이어 뒤에서 위로 번지는 가는 빛 기둥 | 0.25초 |

- 입자는 `Square` 1개 스프라이트(4 × 4px, Point)를 공유하고 색만 스테이지별로 바꾼다. 추가 아트가 필요 없다.
- 이펙트는 플레이어의 자식이 아니라 **월드에 생성되어 `LateUpdate`에서 플레이어 위치를 약 0.4초간 따라간다**(플레이어 좌우 반전·무기 애니메이션의 영향을 받지 않고, 플레이어가 파괴되어도 이펙트가 남아 스스로 사라진다).
- 수명이 끝나면 `Destroy`. 한 번에 1개만 존재하므로 풀링은 쓰지 않는다.

**스크립트·프리팹**
- `SwitchTeleportTrap`에 필드 추가: `[SerializeField] private TeleportArrivalEffect arrivalEffectPrefab;`(비우면 이펙트 없음).
- 신규 `TeleportArrivalEffect`(`Assets/@Scripts/Trap/`): 이펙트 프리팹 루트에 붙어 플레이어 추적(`Follow(Transform)`)·수명 후 파괴를 담당. 입자는 `ParticleSystem`, 바닥 파문은 `SpriteRenderer`+간단한 확대·페이드.
- 프리팹: `P_FX_TeleportArrival_{Stage}` 5개(`@Prefab/Trap/Themed/*/`). 스테이지별 `P_Trap_Teleport_*`의 `arrivalEffectPrefab`에 연결.

**검증**
- [ ] 이동 직후 플레이어 발밑·몸 주변에서 입자와 파문이 보이고 카메라 이동 후에도 화면 안에 있다.
- [ ] 플레이어가 이동 직후 걸어가도 이펙트가 약 0.4초간 따라가고 그 뒤 사라진다.
- [ ] 플레이어를 가리지 않는다(파문은 뒤, 입자는 가벼운 앞).
- [ ] 연속 발동(쿨다운 3초 후 재발동)에도 이펙트가 누적되지 않는다.
- [ ] 이펙트 비활성(`arrivalEffectPrefab` 비움) 시 기존 동작과 같다.

## 14. 설계 변경 — 워프 함정은 스위치 없이 자체가 스위치이며 1회만 발동 (2026-10-17)

### 14-1. 변경 내용

- **스위치 없음**: 워프(텔레포트) 함정은 별도 스위치 판 없이 **마법진 자체가 스위치 역할**을 한다(13항을 확정·구현).
- **1회 발동**: 한 번 발동하면 **더 이상 작동하지 않는다.** 이전의 "쿨다운 3초 후 재발동"을 폐기한다.
- 이 규칙은 **배치된 워프 함정 전부**에 적용한다(스테이지 3·4·5, 낙하 포착형 포함).

### 14-2. 동작

| 단계 | 내용 |
|---|---|
| 대기 | 마법진(`pad`)이 발판 윗면에 놓여 있고 감지 영역이 위에 깔림 |
| 밟음 | 플레이어가 위를 지나가면 즉시 시작점으로 이동(속도 0, 카메라 즉시 이동), 예고 없음 |
| 도착 | 이동한 플레이어 주변에 도착 이펙트(바닥 파문 + 픽셀 입자, 13-8항) |
| 사용 완료 | 출발한 마법진은 충전(`pad_1`) → 발동(`pad_2`) 프레임으로 눌리고, 눌린 채 서서히 어두워져(0.5초) **사용된 상태로 고정** |
| 이후 | 같은 마법진을 다시 밟아도 아무 일도 일어나지 않음 |

### 14-3. 구현 요약

- `SwitchTrigger`: `oneShot`을 켜면 이벤트 발송 **전에** 소진 처리(재진입 방지). `IsOneShot` 속성 추가.
- `SwitchPressAnimation`: 1회성이면 눌림 뒤 `spentTint`(0.45, 0.45, 0.5)로 서서히 어두워지고 복귀하지 않음.
- `TeleportArrivalEffect`(신규) + `SwitchTeleportTrap.arrivalEffectPrefab`: 이동 직후 이펙트 생성. 이펙트 프리팹 `P_FX_TeleportArrival_*`(5개, `@Prefab/Trap/Themed/FX/`), 재질 `M_FX_Pixel`.
- 워프 프리팹 `P_Trap_Teleport_*` 5개: 스위치 판(`ThemedVisual`) 제거, `TeleportRune` → `Pad`(중앙, 로컬 Y -0.02, `sortingOrder` -1), `oneShot = true`, `pressFrames = [pad_1, pad_2]`, 감지 영역 폭 = `max(1.1, 마법진 폭 × 0.9)`.

### 14-4. 적용 결과 (배치된 워프 함정 전수)

| 씬 | 개수 | 내용 |
|---|---|---|
| Stage3 | 35 | 3-3 발판형 30 + 3-4 낙하 포착 5. 모두 `oneShot = true`, 마법진만 남음(낙하 포착 5개는 외형 비활성 유지) |
| Stage4 | 2 | 4-1 낙하 포착(TP1·TP2). 마법진 외형이 공중에 보여 숨김 처리, `oneShot = true` |
| Stage5 | 2 | 5-3 발판형. 마법진이 발판 윗면보다 0.12 아래에 묻혀 있어 윗면에 맞춤(간격 0.00) |

- **낙하 포착형도 1회 발동**이다. 3-4의 5개와 4-1의 2개는 한 번 플레이어를 구한 뒤에는 작동하지 않아, 이후 같은 구간 낙하는 일반 낙사 처리(낙사 시 체력 손실 후 마지막 안전 발판 복귀)로 넘어간다.
- 구형 비테마 프리팹 `P_Trap_Teleport.prefab`을 쓰는 인스턴스는 없다.

### 14-5. 검증 (플레이 모드, 3-3)

- 마법진을 밟으면 시작점(579, 0)으로 즉시 이동하고, 이동한 플레이어 위치에 이펙트가 생성되어 따라간다(보라색 파문 + 입자 확인).
- 사용된 마법진은 `pad_2` 프레임, 어두운 색, 눌린 위치로 고정된다.
- 같은 마법진을 다시 밟아도 플레이어가 이동하지 않는다.
- **미확인**: Stage4·5 워프의 플레이 동작, 3-4 낙하 포착의 1회 발동 후 낙하 처리, 이동 발판 탑승 중 발동, 카메라 이동.
