# Stage1 - Section_2(1-2) 맵 설계안

> Unity 씬 작업은 진행하지 않았습니다(사용자 확인: "설계안만 작성"). 아래 좌표/수치를 검토 후 승인하시면, 별도 요청 시 Unity에서 실제 배치 작업을 진행합니다(규칙 9, 11).

## 1. 컨셉 이미지 해석

| 기호 | 의미 |
|---|---|
| ★ (별) | 구간 시작점 = Section_1 → Section_2 진입 지점(Boundary_1_2) |
| 실선(곡선/직선) | 밟고 지나갈 수 있는 지형(발판) |
| 점선 | **점프해야 하는 갭(빈 공간)** — 사용자 확인 완료 |
| ○ (원) | 구간 종료(목표) 지점 = Section_2 → Section_3 진출 지점(Boundary_2_3) |

전체 흐름: 시작 → 완만한 언덕(굴곡 지형) → 갭 점프 1 → 짧은 발판/계단식 하강 → 갭 점프 2(더 크게 낙하) → 완만한 통로 → 목표.

## 2. 기존 씬 데이터 확인 결과 (Stage1.unity)

- `Section_2`는 현재 `Background_Forest` 배경만 있고 지형(Platform)이 없는 빈 구간입니다.
- 구간 폭: `Boundary_1_2`(x=10.5) ~ `Boundary_2_3`(x=21) → **가로 10.5유닛**.
- 카메라: `Section_2` 앵커 x=13, y=1, `orthographicSize=4`(Section_1 값을 그대로 유지). 이 프로젝트는 **구간별로 카메라가 스크롤되지 않고 고정**되는 방식이라, 구간 내 모든 지형이 한 화면 안에 들어와야 합니다.
  - 화면에 보이는 범위(16:9 기준 추정): x ≈ 5.89 ~ 20.11, y ≈ -3 ~ 5.
  - ⚠️ `Boundary_2_3`(x=21)이 이 계산상 화면 오른쪽 경계(20.11)를 살짝 벗어납니다. 트리거 동작 자체엔 문제없지만, 목표 지점이 화면 끝에 걸쳐 보일 수 있어 추후 Unity 작업 시 `orthographicSize`를 4.2 정도로 살짝 키우거나 앵커를 x=13.5로 옮기는 걸 권장합니다.
- 플레이어 이동 스펙(`Player_Warrior.prefab` 기준: moveSpeed=8, jumpForce=9, gravityScale=3):
  - 최고 점프 높이 ≈ **1.38유닛**
  - 동일 높이 착지 기준 최대 수평 점프거리 ≈ **4.9유닛**(전력 질주 점프)
  - → 갭은 이보다 확실히 작게 설계해야 "점프하면 넘어가지만 실수하면 빠지는" 긴장감이 생깁니다.

## 4. 비고 / 확인 필요 사항

1. 컨셉 이미지는 언덕이 2개, 즉 굴곡이 더 많았지만, 실제 구간 폭이 10.5유닛으로 좁아 언덕 1개로 단순화했습니다. 컨셉대로 굴곡을 더 넣고 싶다면 `Boundary_2_3` 위치를 오른쪽으로 옮겨 구간을 넓히는 방안을 검토해야 합니다(씬 수정 필요).
2. 원본 이미지는 전체적으로 훨씬 큰 낙차(별 위치 대비 원 위치가 화면 대부분을 가로지르는 하강)를 보여주지만, 고정 카메라(세로 8유닛) 안에 담아야 해서 낙차를 y=0→-2.7(약 2.7유닛)로 축소했습니다. 더 극적인 낙하를 원하면 구간 내 카메라 스크롤 기능 추가(코드 수정)가 필요합니다.
3. 위 좌표/폭은 설계 제안이며 실제 배치는 Unity에서 타일맵으로 진행해야 합니다(사용자 승인 시 진행).
