Hero_Knight_2는 그림을 교체하는 2D 애니메이션이므로 기존 기사에게 모션만 직접 리타기팅할 수 없다. 해당 에셋의 자세를 참고해 VARCO 워크플로우에서 현재 기사의 은색 갑옷, 뿔 투구, 붉은 망토, 금색 방패 문양을 갖춘 프레임으로 재생성했다. 생성 결과의 세부 장식과 비율은 원본과 완전히 동일하지 않다. 왼쪽 동작은 같은 그림의 좌우 반전이므로 장비를 든 손도 반전된다.

이동은 12fps 반복 클립이다. 공격은 기존 PlayerCombat의 진행률에 따라 6장을 표시하며, 대쉬는 원본 Hero_Knight_2 시트처럼 정지 포즈를 사용한다. 대기·점프·피격·아이템 습득은 기존 플레이어 동작을 사용한다. 스프라이트는 공통 발 기준점과 표시 크기로 임포트했다. 공격은 높이 측정에 검을 포함해 몸이 축소되는 문제를 피하도록 배율을 유지했다.

기존 Player_Warrior 프리팹 및 기존 스테이지의 플레이어는 이 작업으로 교체하지 않았다.

## 2026-10-08 일반 피격과 무장해제 전환 조건 분리

일반 피격에서 TriggerDamage와 TriggerDisarmed를 함께 호출하던 코드 때문에 피격 포즈가 끝난 뒤 무장해제 그림이 노출됐다. 일반 피격의 무장해제 호출을 제거하고, PlayerSpriteAnimator는 PlayerHealth.IsDisarmed만 참조하도록 바꿨다. 별도의 무장해제 표시 타이머/API는 제거했다.

- 무장 체력 > 0: 피격 리액션만 잠깐 표시한 후 기존 무장 동작으로 복귀.
- 무장 체력 = 0: 기존 EnterDisarmedState에서 무장해제 상태로 전환하고 disarmedMaxHealth만큼 체력을 가득 채운다. 표시도 해당 상태를 따른다.
- 전환 후에는 무장 피격·검 공격·대쉬 그림을 덮어쓰지 않고 무장해제 대기/이동/점프 포즈를 유지한다.
- 무장해제 체력까지 0이면 기존 사망 처리를 사용한다. 상태별 최대체력과 UI 이벤트는 유지한다.
- 적용 파일: Assets/@Test/Scripts/Combat/PlayerHealth.cs, Assets/Scripts/Player/PlayerSpriteAnimator.cs. 공통 스크립트이므로 해당 컴포넌트를 사용하는 테스트 모델과 기존 플레이어에 적용된다.
- Unity 스크립트 반영 및 컴파일 완료, 콘솔 오류 0건. 별도 게임 플레이 테스트는 실행하지 않았다.

## 2026-10-08 베기 공격 8프레임 재제작

사용자의 공격 모션 가독성 피드백을 반영했다. 프로젝트에 있는 Hero Knight - Pixel Art의 HeroKnight_Attack1/2/3 시트와 클립을 살펴 검을 크게 돌리는 준비 동작, 전방을 지나는 베기, 가늘어지는 잔상을 참고했다. 기존 기사 원본 출력을 각 프레임의 직접 입력으로 사용해 VARCO에서 별도로 생성했다.

- 1~2: 검을 뒤/위로 당기는 준비. 3: 베기 시작. 4~5: 큰 전방/아래 방향 베기와 궤적. 6: 후속 동작과 가늘어진 잔상. 7~8: 복귀.
- 실제 출력 1536×1152, 프롬프트에 4K resolution 명시. 넓은 4:3 캔버스로 검과 궤적이 잘리지 않게 했다.
- 워크플로우 마스크로 캐릭터/실제 베기 궤적을 구분하고, 연결된 순백색 배경과 작은 잔여물을 정리했다. 마스크가 추가로 그린 궤적은 원본 RGB를 추가하지 않는 방식과 흰 외곽 정리로 배제했다.
- PNG는 RGBA로 저장했고 공통 PPU 80, 발 최하단 및 부츠 영역의 중앙을 피벗으로 설정했다. 궤적의 폭이 피벗을 밀지 않도록 계산 범위를 제한했다.
- 테스트 프리팹 attackFrames=8, attackVisualDuration=0.5초, attackCooldown=0.52초, 방향 보정 배열=8공격+1대쉬. 좌우 피격 및 체력 0에서만 무장해제로 전환되는 공통 로직은 유지한다.
- 피해 판정 발생 시점은 기존 PlayerCombat의 공격 시작 시점을 유지했다. 이번 작업에서 타격 범위/피해량/피해 판정 시점은 변경하지 않았다.
- 좌우 공격은 기존 테스트 모델 방식처럼 오른쪽용 이미지를 좌우 반전해 표시한다. 장비를 든 손도 반전된다.
- 작업 노드/프롬프트: slash_nodes.json. 이미지 원본: slash_raw, 마스크: slash_masks, 최종 PNG: slash_final, 임포트 설정: slash_import_settings.json.
- 미리보기: Player_Slash_Preview.gif, Player_Slash_Frames.png. GIF에는 반복을 알아보기 쉽게 끝 프레임 정지 시간을 추가했고, 게임에서는 0.5초 동안 한 번 재생한다.
- 콘솔 오류 0건, 프리팹 연결 값 확인. 별도 게임 플레이 테스트는 실행하지 않았다. 기존 연결 검사 파일의 공격 프레임 기대값은 8로 갱신했으며 실행하지 않았다.

## 2026-10-08 동작 간 캐릭터 표시 크기 통일

공격 이미지는 모두 PPU 80으로 임포트했지만 생성된 캐릭터 자체의 픽셀 크기가 프레임마다 달랐다. 이동/대쉬는 자세에 따라 달라지는 몸 전체 높이로 배율을 정했던 것도 크기 차이의 원인이었다.

- 기존 idle_right의 금속 투구 정수리~턱 길이 약 175px, PPU 100을 기준으로 삼았다. 검, 뿔, 베기 궤적 및 웅크린 자세의 전체 높이는 크기 기준에서 제외했다.
- 투구 길이를 이미지에서 수동 측정해 `PPU = 측정 길이 / 175 × 100`으로 설정했다. 생성 그림의 비율 차이 때문에 부위 전체가 픽셀 단위로 동일해지는 것은 아니며, 캐릭터 배율의 시각적 일관성을 맞추는 보정이다.
- HeroKnightTest의 공격 8장, 달리기 8장, 대쉬 1장, 좌우 피격 2장 총 19장에 적용했다. 원본 PNG/알파 및 발 피벗은 그대로 두고 TextureImporter의 PPU만 변경했다.
- 공격 PPU: 98.857, 98.857, 81.714, 95.429, 104.571, 102.286, 97.143, 97.714. 대쉬: 125.714. 좌우 피격: 105.143 / 110.857.

- 측정/배율 기록: hk2_gen/motion_scale_settings.json. Unity에서 읽은 실제 임포트 값: hk2_gen/current_motion_imports.json. 비교 이미지: hk2_gen/Player_Motion_Scale_Comparison.png. 공격 GIF도 새 PPU를 반영하도록 갱신했다.

## 2026-10-08 새 모션의 흰 외곽 매트 정리
