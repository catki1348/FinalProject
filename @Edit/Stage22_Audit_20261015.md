# 2-2 수칙·설계 의도 검수

**판정: 기본 진행 기능은 정상이나 최신 수칙·설계 의도 전체 기준으로는 미통과.** 아래 4개 보완 사항을 확인했다. 이번 요청의 2-2 범위는 검수이므로 본 씬·발판 프리팹을 수정하지 않았다.

기준: `LHS_Custumer.md`, `MapEdit.md`(특히 2026-10-12 발판 길이 조절 기준), `MapDesign_Stage2-2.md`. 실제 데이터는 `Stage22_Audit_20261015.json`, 모델 검사 결과는 `Stage22_AuditResults_20261015.json`이다.

## 보완 사항

### 1. 발판 18개가 Tiled 기준을 따르지 않음 — P2

18개 모두 SpriteRenderer.drawMode=Simple이다. 일반 N1~N10의 월드 X Scale은 각각 3 / 1.5 / 2.5 / 2 / 2 / 2 / 2 / 2.5 / 2.5 / 3으로, Transform으로 외형을 늘리는 구방식을 사용한다. 이는 최신 MapEdit의 **Scale 1 + Tiled/Continuous + 명시적 SpriteRenderer.size/콜라이더 크기** 기준과 다르다.

실제 N1 폭은 3.300, N2는 1.650, N3는 2.750으로 표의 3.0 / 1.5 / 2.5보다 10% 크다. N1 윗면은 0.525, 설계 표는 0.0이다. 표는 최초 상대 좌표/높이를 혼용하고 있으므로 변환 시 현재 물리 윗면·폭을 보존할지 최초 표 수치로 복원할지 먼저 정해야 한다. 외형 수정만 하면서 콜라이더를 표 수치로 덮으면 점프 간격까지 함께 바뀐다.

권장: 2-2 전용 Tiled 원본/변형을 만들고 현재 물리 발판 크기·윗면·이동 경로를 보존하면서 외형 방식을 먼저 정규화한다. 공용 정글 원본을 무작정 변경하면 다른 영역까지 영향을 준다.

### 2. 특수 발판 8개가 전용 프리팹 원본에 구성되지 않음 — P2

MP1~MP5와 D1~D3 모두 가장 가까운 프리팹 원본이 `Platform_Stage2_Jungle.prefab`이며, MovingPlatform/DisappearingFoothold는 **씬에 추가된 컴포넌트**다. 타입별 재사용 구성이 원본 프리팹으로 보존되지 않아 LHS 수칙 38의 반복 오브젝트 원본 관리 기준과 맞지 않는다.

권장: 이동형/소멸형을 전용 변형 프리팹으로 만들고 각 배치의 경로·속도·소멸 설정을 유지한다. 문서 첫머리의 “MovingPlatform_Stage2_Jungle/Foothold_Disappearing_Stage2_Jungle를 사용했다”는 과거 기록도 현재 씬과 다르다.

### 3. 소멸 발판 3개를 모두 밟는 흐름은 강제되지 않음 — P2, 설계 의도 차이

설계 §3·§4는 소멸형 3개를 연속으로 밟는 긴장 구간으로 설명한다. 실제 기본 속도 8, 점프 속도 9, 중력 29.43에서 임시 씬의 물리 점프로 다음을 확인했다.

| 출발 | 최초 상면 착지 | 결과 |
|---|---|---|
| N8 오른쪽 끝 (135.58, 약 2.05) | D2, 약 0.62초 후 | D1을 건너뜀 |
| D1 오른쪽 끝 (137.95, 약 2.02) | D3, 약 0.62초 후 | D2를 건너뜀 |

발판 수 3개는 맞지만 모두를 밟게 하는 구조는 아니다. 사용자가 원래 지정한 “소멸형 3개 배치” 자체는 충족한다. 이 지적은 설계 문서의 상세 진행 의도에 대한 차이이며 게임 진행 불가 문제는 아니다.

권장: 세 개를 반드시 밟게 하려면 단차·가장자리 간격 또는 경로 구조를 다시 설계하고, 인접 도달은 80% 성능으로 유지하면서 두 칸 건너뛰기는 제한하는 검증을 추가한다. 현재 위치에서 단순히 모두 멀리 옮기면 마지막 N9 및 종료점/영역 폭도 재검토해야 한다.

### 4. 거리 척도 환산 오류와 문서 상태 혼재 — P2, 문서

설계 §5는 **88.9유닛을 “이동 동선 길이 ≈89, 척도 1~100”**으로 적었다. 규칙 15는 8유닛=척도 1이므로, 그 합산값을 전제로 한 척도는 **약 11.11**이다. 88.9는 월드 유닛 값이며 척도 89가 아니다. 현재 실제 정적 발판 폭 합도 28.30으로 최초 표의 26.0과 달라, 실제 동선 거리 자체는 좌표·탑승 기준을 정해 재산출해야 한다.

문서 상단의 구현 완료 기록, 이어지는 “Unity 작업은 아직 진행하지 않았다” 문장, 옛 카메라 폭/종료점 좌표도 서로 다른 시점의 기록이다. 최신 상태 요약을 한 곳으로 정리하는 것이 필요하다.

종료점의 에디터 저장값 isTrigger=false는 ZoneEndPoint.Awake가 true로 전환한다. 실제 실행 전환을 확인했으므로 진행 결함으로 분류하지 않았다.

## 검수 범위와 보존

Test022는 Stage2 복사본으로 만들어 테스트 후 삭제했다. 정면·후면·좌·우·상면 임시 렌더를 확인했고 스크린샷은 삭제했다. 2D 스프라이트의 측면/상면은 면적으로 보이지 않으며, 판정 근거는 콜라이더·렌더러 설정과 물리 검사다. 키보드/마우스로 영역 전체를 연속 완주하는 검사는 수행하지 않았다.

검수 전후 Stage2 SHA256은 `0D6FC561F708760EAC86515B5AF7230EBD989570F9E10D458CA6FDEA27893994`로 동일하다. 본 씬/프리팹 수정 및 커밋·푸시는 하지 않았다. 필요한 수정은 위 우선순위대로 별도 진행할 수 있도록 근거를 남겼다.
