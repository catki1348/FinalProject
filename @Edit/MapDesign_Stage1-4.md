# Stage1 - Section_4(1-4) 맵 설계안

> Unity 씬 작업은 진행하지 않았습니다(사용자 지시: "설계만 하고 유니티에는 작업하지 마라"). 아래 좌표/수치를 검토 후 승인하시면, 별도 요청 시 Unity에서 실제 배치 작업을 진행합니다(`LHS_Custumer.md` 규칙 9, 11).

## 1. 설계 목표

1-3까지는 "이동형 발판 1개 + 완만한 지형"으로 비교적 단순했습니다. 1-4는 **보스존(1-5) 직전 마지막 구간**이므로, 지금까지 확보된 모든 기믹(설계안 포함)을 조합해 플레이어가 다양한 유형의 도전을 연속으로 겪도록 설계하고, 마지막에는 보스전을 준비할 수 있는 여유 구간으로 마무리합니다.

- 지금까지 등장한 기믹: 갭 점프(1-2), 수평 이동형 발판(1-3).
- 이번에 새로 도입하는 기믹: **수직 이동/등반**, **소멸형·점멸형·피해형 발판**(`PlatformDesign_InteractiveFootholds.md` 설계 적용), **몬스터 조우**(`Monster.md` 규칙 적용), **경로 분기(선택형 루트)**.

## 2. 기존 씬 데이터 확인 결과 (Stage1.unity)

- `Section_4`는 현재 배경(`Background_Forest`)과 `ZoneStartPoint`(로컬 x=0), `ZoneEndPoint_1-4`(로컬 x=30)만 있고 지형이 없는 빈 구간입니다. → **구간 폭 30유닛**(월드 x=147~177), 좌표는 모두 Section_4 로컬 기준(로컬 0 = 월드 147)으로 표기합니다.
- `Boundary_4_5`(카메라 구간 전환 트리거)는 현재 로컬 x=19(월드 166) 지점에 있습니다. 아래 설계의 5번 구간(스카이브릿지, 로컬 x=17.5~22.5) 중간에 걸립니다 → **비고 4번 참고, 구현 시 위치 조정 권장**.
- Section_4의 `CameraBoundsZone`은 Section_3/5와 동일한 기본값(29.57 × 16.9, `orthographicSize=5`)을 그대로 물려받은 상태입니다.
- **카메라 방식 정정**: `MapDesign_Stage1-2.md` 작성 당시엔 "구간별 카메라 고정(스크롤 없음)"으로 가정했으나, 실제 구현은 `PlayerCameraFollow` + `CameraBoundsZone` 방식입니다. 즉 구간 내에서는 카메라가 플레이어를 따라 스크롤되고, `Boundary` 트리거를 지날 때만 다음 구간의 바운즈로 전환됩니다. Section_4는 폭 30유닛으로 화면 폭보다 넓어 스크롤이 필수이므로, 이 설계는 스크롤 카메라를 전제로 합니다.
- 플레이어 이동 스펙(`Player_Warrior.prefab` 기준, 1-2 문서와 동일하게 확인됨): moveSpeed=8, jumpForce=9, gravityScale=3 → 최고 점프 높이 ≈ **1.38유닛**, 동일 높이 기준 최대 수평 점프거리 ≈ **4.9유닛**.
- 1-3에서 이미 쓰인 이동형 발판(`MovingPlatform` + `PlatformPath`, `loopMode=PingPong`) 구조를 그대로 재사용하되, 이번엔 **수직 경로**로 새롭게 조합합니다.

## 4. 비고 / 확인·의존성 필요 사항

1. **`Boundary_4_5` 위치 조정 권장**: 현재 로컬 x=19(월드 166)에 있어 5번 구간(점멸 스카이브릿지, 17.5~22.5) 중간에서 카메라 바운즈가 Section_5로 전환됩니다. 장애물 중간에 카메라 전환이 끼면 위화감이 있으므로, 구현 시 `Boundary_4_5`를 `ZoneEndPoint_1-4`와 같은 로컬 x=30(월드 177)으로 옮기는 것을 권장합니다(씬 수정 필요, 규칙 9/11에 따라 승인 후 진행).
2. **발판 스크립트 선행 구현 필요**: 소멸형(`DisappearingFoothold`)/점멸형(`BlinkingFoothold`)/피해형(`DamageFoothold`)은 `PlatformDesign_InteractiveFootholds.md`에 설계만 되어 있고 아직 승인·구현 전입니다. 1-4를 실제로 배치하려면 그 문서의 8항 순서대로 스크립트 구현이 먼저 진행되어야 합니다.
3. **몬스터 관련 스크립트도 미구현**: 현재 씬/코드베이스에 몬스터 스탯 스크립트, 패턴 스크립트(`IMonsterPattern` 등)가 존재하지 않습니다(`Monster.md` 규칙 2~5). 3번 구간(몬스터 조우)을 실제로 넣으려면 이 스크립트들을 먼저 구현해야 합니다. 제시한 스탯(체력30/공격8/방어2, 패트롤 ±1.5·속도1.5)은 밸런스 기준이 아직 없어 임시값이며, 실제 조정이 필요합니다.
4. **Section_4의 `CameraBoundsZone` 재확인 필요**: 현재 크기(29.57×16.9)는 Section_3/5와 동일한 기본값을 그대로 물려받은 상태입니다. 이번 설계의 수직 구간(y=0~6.5)이 실제 화면(세로) 경계 안에 온전히 들어오는지 Unity 작업 시 재확인이 필요합니다.
5. **1-2 문서 정정 참고**: `MapDesign_Stage1-2.md`가 가정한 "구간별 고정 카메라"는 실제 구현(스크롤 카메라 + `CameraBoundsZone`)과 다릅니다. 이 사실은 향후 1-2 구간을 재검토하거나 1-5(보스존)를 설계할 때도 참고해야 합니다.
6. 본 문서의 좌표/폭/스탯은 설계 제안이며, 실제 배치·스크립트 구현은 모두 Unity/코드 작업이므로 사용자 승인 후 별도로 진행합니다(규칙 9, 11).
