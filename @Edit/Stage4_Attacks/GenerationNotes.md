## 실패와 보정

처음8프레임 시트는 방향·팔 형태 변화와 잘림이 있어 채택하지 않았다. 공격별2프레임 시트에서도 불투명 배경과 잘림이 반복되어 첫3종은 개별 원화 생성으로 전환했다. 자홍색 배경 후보에서 발톱 색이 변해 녹색 배경과 붉은 색 지정으로 수정했다. 낙석은 전신을 포함한2프레임 시트를 채택했다.

`build_attacks.py`는 녹색을 알파로 제거하고, 연결되지 않은 효과·배경 조각을 제거한다. RGB 원화는 다시 칠하지 않는다. 각 자세를 비율 유지한 균일 배율로 보정하고 발 영역 중앙·최하단을 공통 피벗에 맞춘다. 모션별 배율·발 중앙 위치·원본 바운드는 `animation_manifest.json`에 있다.
최종 PNG는1432×1198, RGBA, 발 접지선1190px이다. 단 하단 휩쓸기는 뻗은 팔 때문에 2200×1198이며(피벗 가로 중앙·접지선 동일), 타격 자세 배율을 1.51로 올려 준비 자세와 몸 크기를 맞췄다(2026-10-13 수정). GIF는보기 편하도록716×599의 어두운 배경으로 재생하며, 소스PNG는 투명하다.

## 수칙과 검수

- 수칙8·18: 연결된 워크플로우를 사용하고4K를 요청했다.
- 수칙13·21: Run All을 사용하지 않고 독립 노드만 실행하며 실패 결과를 재처리했다.
- 수칙9·11: Unity 실행·에셋 임포트·씬 변경 없이 파일 제작만 수행했다.
- 수칙22·27: 사용자가 이번2D 작업에 원본 비교·오른쪽 재생·왼쪽 재생·준비 자세·타격 자세의5가지 검수를 승인했다. 상태 확인용 캡처는 디스크 파일을 만들지 않고 확인했다.
- 수칙40: 추출·배경 제거·정렬·재생 기능의 설명 주석을 작성했다.
- 수칙46: Git 커밋·푸시를 수행하지 않았다.
- 수칙48: 이번 저장본의 개별 파일은 모두3MB 미만이다. 3MB 이상 결과가 추가되면 지정된 외부 저장 위치로 옮긴다.

8개PNG의 캔버스·알파·원본 잘림 없음, 4개GIF의 반복 프레임, 준비/타격 전환 시각, 좌우 반전, HTML 이미지 로딩과 컨트롤을 확인했다. 브라우저 오류0이다.
생성 원화 특성상 피부와 팔·목의 세부 묘사는 자세 사이에 차이가 남는다. 이번 결과는 공격당2개의 키포즈를 전환하는 시안이며, 리깅이나 중간 관절 보간은 포함하지 않는다. 실제4K·전체18프레임·독립VFX2장·Unity 전투 구현의 완료로 표시하지 않는다.
