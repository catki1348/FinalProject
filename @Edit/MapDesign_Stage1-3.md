## 1. 요청 사항 정리

- 이번 설계는 별도 컨셉 이미지 없이, **일반 발판(정적) 10개 + 이동형 발판(움직이는 발판) 10개**, 총 20개의 발판만 사용해 1-3 구간을 구성하는 것이 목표입니다.
- `MapEdit.md` 규칙(★=시작, ○=골인, 규칙 3 `스테이지-영역` 표기)은 그대로 적용하되, 이번 구간은 소멸형/점멸형/피해형 발판이나 몬스터 같은 다른 기믹은 사용하지 않고 "일반 발판"과 "이동형 발판"만으로 리듬을 만듭니다.

## 2. 기존 씬 데이터 확인 결과 (Stage1.unity)

- `Section_3`는 월드 x=90(`Boundary_2_3`) ~ x=128(`Boundary_3_4`) 사이, **폭 38유닛**입니다. `Section_3` 오브젝트 자체의 피벗은 월드 x=109, y=1에 있습니다.
- 현재 `Section_3`에는 이미 다음이 배치돼 있습니다.
  - `ZoneStartPoint_1-3` — Section 로컬 (-12.52, 5.1) = 월드 (96.48, 6.1)
  - `Platform_GrassStone` × 2 — 시작 지점 바로 앞 발판 (로컬 약 -11.94~-8, y≈4)
  - `MovingPlatform_1-3` + `PlatformPath`(웨이포인트 2개, 로컬 x -8→+6, y=4, 이동거리 14유닛, `PingPong`) — 기존에 있던 수평 이동형 발판 1개
  - `Background_Forest`(로컬 0,0, scale 2.2) — `MapDesign_Stage1-4.md` 4번 비고와 동일하게, 이 스케일은 구간 폭 38유닛 전체를 덮지 못합니다(카메라 스크롤 범위 부족 가능성, 3번 참고).
  - ⚠️ 확인 중 `MovingPlatform_1-3` 오브젝트 자체의 저장된 y좌표(-19.45)가 그 경로(`PlatformPath`, y=4)와 크게 어긋나 있는 것을 발견했습니다. `MovingPlatform.cs`가 `Start()`에서 위치를 경로의 첫 지점으로 강제 스냅하므로(코드 51행) 실제 플레이에는 영향이 없을 가능성이 높지만, 에디터상 저장 값 자체는 이상 데이터입니다. 이번 설계 승인 후 실제 배치 시 이 오브젝트를 재활용하면서 값도 함께 정리하는 것을 권장합니다.
- 플레이어 이동 스펙(`Player_Warrior.prefab`: `moveSpeed=8`, `jumpForce=9`, `gravityScale=3`, 기존 문서들과 동일):
  - 최고 점프 높이 ≈ **1.38유닛** → 이보다 낮은 턱은 도보 점프로 오를 수 있음.
  - 동일 높이 기준 최대 수평 점프거리 ≈ **4.9유닛** → 이보다 넓은 간격은 이동형 발판 탑승이 사실상 강제됨.
- 이동형 발판 구조는 기존 `MovingPlatform_1-3`과 동일하게 `MovingPlatform.cs`(speed/loopMode) + `PlatformPath.cs`(웨이포인트) 조합을 그대로 재사용합니다. 스크립트는 이미 구현·검증된 상태라 별도 선행 구현이 필요 없습니다.
- 카메라: 다른 섹션과 동일하게 `PlayerCameraFollow` + `CameraBoundsZone` 스크롤 방식(`MapDesign_Stage1-4.md` 정정 사항 참고). `Section_3`의 `CameraBoundsZone`도 Section_2/4와 동일한 기본값(29.57×16.9)을 물려받은 상태로 보이며, 구간 폭 38유닛 전체를 커버하는지는 실제 배치 시 재확인이 필요합니다.
