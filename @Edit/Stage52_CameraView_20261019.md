# 5-2 카메라 시야 수정 (다음 발판이 화면 밖)

2026-10-19. 요청: 5-2에서 S1_B1 구간에서 S1_B2가 플레이 시 메인 카메라 시야로 들어오지 않는다. 다른 발판 다수에도 같은 문제가 있다.

## 원인
- 5-2는 `Section_2` 구간 하나(카메라 크기 5, 화면 높이 10 / 폭 약 17.8)로 묶여 있고 카메라는 플레이어 중심으로 따라간다.
- 이동형 발판이 위아래로 길게 이어지는 곳에서는 다음 발판이 플레이어에서 9~15유닛 떨어져 화면(±5) 밖에 있다. S1_B1 위에 서 있는 동안 S1_B2는 **한 번도** 시야에 들어오지 않았다(5.0 기준 0%, 시야에 들이려면 최소 7.4 이상 필요).
- 5-2 연속 발판 66쌍 중 28쌍이 항상 보이지 않았고(`Analyze_Stage52_CameraView.py`), P1 B 사슬·P3 승강 구간·P5 F1/F3에 집중돼 있었다.

## 수정
- `CameraZoomVolume.cs`(신규): 플레이어가 안에 있는 동안 카메라를 정해진 크기 이상으로 넓히는 트리거 구역. 겹치면 가장 큰 값.
- `PlayerCameraFollow.cs`: 구간 기본 크기와 들어가 있는 확대 구역 중 최댓값을 목표 크기로 보간(기본값은 그대로이므로 다른 영역·구간은 동작 변화 없음).
- `Stage5.unity`: `Section_2/CameraZoom_5-2` 아래 확대 구역 24개. 각 구역은 해당 발판의 이동 범위 + 여백이고, 크기는 "그 발판에서 다음 발판이 보이는 최소 크기"(`Plan_Stage52_CameraZoom.py`, `Stage52_CameraZoom.json`).

| 구간 | 확대 크기 | 구역 수 |
|---|---:|---:|
| P1 A5, B1~B5 (아래로 이어지는 이동형 사슬) | 11.0 ~ 12.5 | 6 |
| P2 이동형 연결 6곳 | 6.0 ~ 6.5 | 6 |
| P3 승강·셔틀 | 7.0 ~ 11.5 | 8 |
| P5 F1·F3 | 8.5 ~ 10.0 | 4 |

기준: 플레이어가 서 있는 발판에서 **다음 발판의 가장 가까운 가장자리**가 화면 안(여백 0.8)에 있을 것. 연속 표시 요구는 11.5까지만 걸고, 그보다 먼 승강기는 "점프 가능 시점 1초 전부터" 보이게 했다.

## 검증
- 이동 모델 시뮬레이션(40초): 확대 구역 적용 후 **점프 가능 구간(1초 전 포함)에서 다음 발판이 화면 밖인 쌍 0개**. S1_B1→B2를 포함한 P1 B 사슬은 항상 보인다. 승강기 6쌍(A5→B1, B5→C1, P3 B1→E1 등)은 승강기가 멀리 가 있는 동안은 화면 밖이지만 점프 가능해지기 전에 들어온다.
- Unity 플레이 확인: S1_B1 구역에 플레이어를 두면 카메라 크기가 5 → 11.5로 올라가고, 구역을 벗어나면 5로 돌아간다. 콘솔 오류 없음.
- 확인하지 않은 것: 실제 입력으로 B1~B5를 연속으로 타는 플레이. 화면이 넓어져(높이 약 23) 캐릭터가 작게 보인다. 크기를 줄이면 앞 발판이 다시 화면 밖이 되므로, 줄이려면 발판 간 수직 거리를 줄이는 설계 변경이 필요하다.
