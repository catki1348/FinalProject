# 4-2 질주 구현·검증 기록

`Assets/Scenes/Stage4.unity`의 Section_2에 구현했다. 전체 거리 480, 시작 X=110, 종료 X=590. 발판은 하나이며 양 끝 여유를 포함한 실제 폭은 488이다. Scale=(1,1,1), Tiled/Continuous, 두께 1, 윗면 Y=0이다. 4-3·4-4와 관련 경계는 X+468 이동했고, 카메라 영역은 4-1→4-2→4-3→4-4 순서로 서로 겹치지 않는다. 5영역 위치는 유지했다.

## 구성

- `RunwayDamage`: 접지 누적 0.5초마다 실제 체력 1 감소. 공중에서는 일시 정지하고 착지 후 이어가며 영역 이탈 시 초기화한다. 기존 일반 피격 무적·방어·피격 애니메이션과 분리한다.
- `PlayerHealth.TakeEnvironmentalDamage`: 방어/무적을 건드리지 않고 기존 무장해제·사망 이벤트 경로로 체력 감소를 처리한다.
- `RunwayEncounterManager`: 80유닛마다 한 무리를 최초 1회 활성화한다. 전멸은 요구하지 않고 종료점은 기존 StageManager로 4-3 전환한다.
- `P_Stage42_DamageRunway`, `P_Stage42_FlyingChaser`: 기존 프리팹에서 만든 전용 변형. 비행종 60마리, 기본 공격/방어 10, 추격속도 9, 감지 (24,10), 대기 반경 0.35. 기준 캐릭터 공격 10이므로 체력 2로 설정해 최소 피해 1 기준 2타 처치다.
- `MonsterMovementBounds`: 저공 추격 중 바닥에 파묻히지 않도록 하한을 유지한다. 재사용한 기존 경계 처리이며 다른 몬스터 원본은 변경하지 않았다.
- 회복 +20과 가속 +5%/최대 5중첩/5초 갱신을 각각 100% 드롭한다. 확률 1은 난수 판정을 생략하도록 `MonsterItemDropper`를 수정하여 Random.value==1의 경계에서도 확정 드롭을 보장한다.
- 바닥은 붉은 틴트로 표현한다. 폭 전체에 초당 수천 개의 파티클을 생성하지 않는다. Stage4 기존 배경을 재사용한다.

Unity의 Tiled 변경 시 Transform Scale이 자동 변경되는 문제를 물리 검증으로 발견하여 최종 Scale 재설정 및 원본 전용 프리팹 수정을 완료했다. fixedDeltaTime 직렬화 부동소수점 오차는 피해 누적에서 10마이크로초 허용치로 처리했다.

검증은 임시 씬의 실행 상태에서 API·물리 시뮬레이션 및 검 공격/획득 판정을 구동한 결과다. 입력을 직접 조작해 전체 구간을 연속 완주하는 난이도 테스트는 수행하지 않았다. 가속 만료는 시간을 기다리는 대신 만료 시점을 설정해 해당 분기를 검증했다. 아이템 전체 동시 상한 20개·각 수명은 기존 규칙을 유지하므로 오래된 아이템은 소멸할 수 있다.

검증 후 Test042만 삭제하고 Stage4를 다시 열었다. 기존 Test000·Test041은 건드리지 않았다. 적용 전 Stage4/PlayerHealth/MonsterItemDropper 사본은 `@Backup/Stage42_20261015`에 보관했다. 커밋·푸시는 수행하지 않았다.
