# 스위치 발판 융화 + 작동 애니메이션 설계안

> 이 문서는 설계만 다룹니다. 스크립트 작성, 프리팹·씬 수정 등 Unity 작업은 `LHS_Custumer.md` 규칙 9, 11에 따라 사용자 승인 후 별도로 진행합니다.
> 대상: 스위치형 함정 전체(투사체 스위치·텔레포트 스위치). 기반 문서: `TrapDesign_SwitchZoneMonster.md`, `TrapDesign_SwitchTeleport.md`.

## 1. 요구사항

1. 스위치가 발판 위 허공에 떠 있지 않고 **발판과 한 몸처럼 보이도록** 배치한다.
2. 플레이어가 스위치를 밟으면 **스위치 작동 애니메이션**이 재생된다.

## 2. 현황 실측 (2026-10-14, 열려 있는 씬 기준 아래 방향 레이캐스트)

| 영역 | 스위치 | 발판 윗면 대비 스위치 기준점 높이 | 비고 |
|---|---|---|---|
| 3-1 | 투사체 10 | **+0.30** 전부 | 발판 두께 0.5, 스위치 스프라이트가 윗면에서 0.30 떠 있음 |
| 3-3 | 투사체 20, 텔레포트 30 | **+0.30** 전부 | 동일 |
| 3-4 | 투사체 `P1`·`P2`·`P4`·`P6`·`P7`·`P8`·`P9`·`P10` | **+0.70** | 설계서의 "서는 면 + 0.7" 규칙 그대로 |
| 3-4 | `P3` | 이동 발판 `M1` 위 **3.8** | 리프트 통로 안 공중 |
| 3-4 | `P5` | 아래에 충돌체 없음 | 셔틀 통로 안 공중 |

원인 3가지:
1. **기준점이 윗면 위에 있다.** 스위치 루트가 윗면 + 0.30(3-1·3-3)/+0.70(3-4)에 놓이고, 스프라이트(`T_Trap_Switch_*`, 약 1.08 × 0.57 유닛)는 루트에서 위로 그려져 바닥이 그대로 뜬다.
2. **발판과 정렬 순서·접합 처리가 없다.** 스위치(sortingOrder 12)와 발판(0)이 따로 놀고, 스위치가 발판 속으로 박히는 부분이 없다. 노란 사각형 임시 스프라이트(`Visual`, 0.71 × 0.71)도 남아 있다.
3. **감지 영역이 몸통 높이다.** 3-1·3-4는 트리거가 1.0 × 1.4로 높아 "밟는" 동작이 아니라 스치기만 해도 발동한다(3-3은 이미 1.1 × 0.18 판형).
4. **작동 연출이 없다.** 스위치 스프라이트는 단일 이미지이고 `Animator`도 없다.

## 3. 설계 1 — 발판 융화 (매립형 스위치)

### 3-1. 배치 규칙

1. 스위치 루트(`Transform.position.y`)는 **발판 윗면과 같은 높이**에 둔다(떠 있는 간격 0). X는 기존 설계 좌표 유지.
2. 스프라이트는 **아래쪽 30%(약 0.17유닛)를 발판 속에 묻는다.** 지금 스프라이트 크기 기준으로 `ThemedVisual` 로컬 Y = `+0.115`(현재 `+0.29`). 눈에 보이는 높이는 약 0.40.
3. 묻힌 부분이 보이지 않도록 스위치 `sortingOrder`를 발판 바로 뒤(`-1`)로 낮춘다. 발판(order 0)이 앞에서 덮으므로 윗면 위로 솟은 부분만 보여 **발판에 박힌 버튼**처럼 보인다.
4. 임시 `Visual`(노란 사각형)은 제거한다.
5. 텔레포트 스위치의 `TeleportRune`(옆 장식)도 루트가 내려가면서 바닥이 윗면에 닿는다. 별도 이동 불필요.
6. **이동형 발판 위에 두는 스위치는 그 발판의 자식으로 둔다**(발판과 같이 움직임). `MovingPlatform`의 탑승자 목록은 플레이어 `Rigidbody2D`만 다루므로 영향 없음.

### 3-2. 감지 영역 통일 (판형)

| 항목 | 값 |
|---|---|
| `BoxCollider2D` | 크기 **1.1 × 0.18**, 오프셋 **(0, 0.09)** (3-3에서 이미 쓰는 값) |
| 효과 | 발판 윗면 위 0 ~ 0.18 구간에 발이 닿아야 발동 → **"밟는" 동작에서만 작동**, 점프로 위를 지나가면 발동하지 않음 |

3-1·3-4의 1.0 × 1.4 트리거는 이 값으로 교체한다. 루트가 윗면과 같아지므로 판 영역이 윗면 바로 위에 정확히 깔린다.

### 3-3. 공중 스위치 처리 (3-4 `P3`·`P5`)

"허공 통로에 둔다"는 설계 자체가 융화 규칙과 충돌한다. 기본안(A):

- **A (권장)**: 해당 리프트/셔틀의 **발판 상판에 매립해 자식으로** 둔다. 탑승하면 밟게 되므로 발동 시점이 "통로 안 특정 지점 통과"에서 "**탑승 즉시**"로 바뀐다. `P3`(`M1`)은 발사기가 위(65, 24)에 있어 발동 후 탄이 낙하해 리프트 상승 경로와 만나는 시점이 달라지므로 **탄도·시점 재검증 필요**.
- B: 통로 벽/바닥의 고정 발판에 두고 경로를 그쪽으로 우회시킨다. 맵 재설계가 필요해 비권장.

## 4. 설계 2 — 작동 애니메이션

### 4-1. 방식: 코드 연출(`SwitchPressAnimation`)

스프라이트가 단일 이미지라 눌린 상태 이미지가 없다. 아트 추가 없이 **스프라이트를 아래로 눌러 발판 속으로 밀어 넣는** 연출로 처리한다. 매립형(3-1항)이라 눌릴수록 발판 속으로 사라져 자연스럽다.

| 단계 | 시점 | 동작 |
|---|---|---|
| 눌림 | 스위치 발동 순간 | `visual`이 아래로 **0.14유닛** 이동(0.08초, ease-in), 색을 `pressedTint`로 어둡게 |
| 유지 | 쿨다운 동안 | 눌린 상태 유지(발동 불가 상태가 눈에 보임) |
| 복귀 | 쿨다운 종료 | 원위치 + 원래 색으로 **0.20초** ease-out |
| 1회성(`oneShot`) | 복귀 없음 | 눌린 채로 고정(레버형) |

선택: `pressedSprite`를 지정하면 눌림 때 스프라이트를 교체한다(나중에 전용 아트가 생겼을 때용). 텔레포트 스위치는 `pulseTarget`(룬)을 발동 순간 0.3초 동안 1.0 → 1.25 → 1.0배로 부풀려 어떤 함정이 작동했는지 알려 준다.

### 4-2. 스크립트 변경

**신규** `Assets/@Scripts/Trap/SwitchPressAnimation.cs` (규칙 39: 감지는 `SwitchTrigger`, 연출은 이 스크립트가 분리 담당)

```csharp
// SwitchTrigger 이벤트를 구독해 스위치 스프라이트를 눌렀다 복귀시키는 연출 컴포넌트.
public class SwitchPressAnimation : MonoBehaviour
{
    [SerializeField] private SwitchTrigger switchTrigger;
    [SerializeField] private Transform visual;                     // 눌릴 스프라이트(ThemedVisual)
    [SerializeField] private SpriteRenderer tintTarget;            // 색 변경 대상(보통 visual과 동일)
    [SerializeField] private float pressDepth = 0.14f;
    [SerializeField] private float pressDuration = 0.08f;
    [SerializeField] private float releaseDuration = 0.2f;
    [SerializeField] private Color pressedTint = new Color(0.6f, 0.6f, 0.6f, 1f);
    [SerializeField] private Sprite pressedSprite;                 // 선택: 지정 시 눌림 때 교체
    [SerializeField] private Transform pulseTarget;                // 선택: 텔레포트 룬 등
}
```

- 구독: `switchTrigger.OnActivated`(눌림), 신규 `switchTrigger.OnReady`(복귀).
- 코루틴은 한 번에 하나만 돌리고 새 요청이 오면 이전 것을 끊는다. `WaitForSeconds`·`Color`·초기 위치는 필드에 캐싱(규칙 43, `Update` 할당 없음).
- 비활성화되면 구독 해제 후 원래 위치/색/스프라이트로 복원.

**기존 파일 수정 1건** `SwitchTrigger.cs`: 쿨다운이 끝나는 순간 알리는 이벤트 추가(기존 동작 무변경).

```csharp
// 쿨다운이 끝나 다시 발동 가능해진 순간(반복형 스위치만 발생. 복귀 연출용)
public event Action OnReady;

// Update 안: 기존 쿨다운 감소 블록에서 타이머가 0 이하가 되는 프레임에 1회 호출
if (cooldownTimer > 0f) { cooldownTimer -= Time.deltaTime; if (cooldownTimer <= 0f) OnReady?.Invoke(); }
```

### 4-3. 프리팹 구성 (승인 후)

`P_Trap_Switch`와 `P_Trap_TeleportSwitch`(3-3에서 사용 중인 것 포함)를 공통 구성으로 정리한다.

| 구성 | 값 |
|---|---|
| 루트 | `BoxCollider2D`(1.1 × 0.18, 오프셋 0, 0.09, 트리거), `SwitchTrigger`, `SwitchPressAnimation` |
| 자식 `ThemedVisual` | 스테이지별 `T_Trap_Switch_*` 스프라이트, 로컬 Y +0.115, sortingOrder -1 |
| 텔레포트 전용 | 자식 `TeleportRune` + `SwitchTeleportTrap`, `pulseTarget`에 룬 연결 |
| 제거 | `Visual`(노란 임시 사각형) |

## 6. 설계 수치 검증 (손계산 금지, 스크립트로 확인)

1. 모든 스위치의 루트-윗면 간격이 0.05 이하.
2. 스프라이트가 발판 속에 묻힌 깊이(0.17)가 발판 두께(0.5)보다 작아 반대편으로 비치지 않음.
3. **판형 감지 영역으로 바뀐 뒤에도 정상 동선에서 반드시 밟히는지**: 3-4 저격형은 기존 1.4 높이 트리거가 점프로 지나가던 경우도 잡았으므로, 각 스위치가 착지 발판의 **걸어 지나가는 경로 위**에 있는지 동선 시뮬레이션으로 확인한다(발판이 짧아 건너뛰는 경우 스위치 X 조정).
4. `P3`·`P5` 상판 매립 후 탄이 탑승 중인 플레이어와 만나는지(탄도-구간 최소거리 재계산, 예고 0.5초 지연 반영).
5. 이동형 발판 위 스위치가 발판과 같이 움직이고 `MovingPlatform` 탑승 처리에 영향이 없는지.

## 7. 플레이 검증 체크리스트 (규칙 24: 임시 씬에서 수행 후 정리)

- [ ] 스위치가 발판 윗면에서 뜨지 않고 박힌 것처럼 보인다(3-1·3-3·3-4 각 영역 확인).
- [ ] 밟는 순간 눌림 연출 → 쿨다운 중 눌린 상태 유지 → 쿨다운 종료 시 복귀한다.
- [ ] 쿨다운 중 재접촉해도 연출이 겹치거나 튀지 않는다.
- [ ] 점프로 스위치 위를 지나가면 발동하지 않는다.
- [ ] 텔레포트 스위치는 룬이 발동 순간 부풀었다 돌아온다.
- [ ] 이동형 발판 위 스위치가 발판과 같이 움직인다.
- [ ] 오브젝트가 비활성화되었다 켜져도 눌린 상태가 남지 않는다.
- [ ] 기존 투사체 발사·텔레포트 동작이 변하지 않는다.

## 8. 확인 필요 사항 (확정됨)

1. **`P3`·`P5` 처리**: 기본안 A(상판 매립, 탑승 즉시 발동)로 진행해도 되는지. 발동 시점이 바뀌어 탄도 재검증이 필요합니다.
2. **매립 깊이**: 스프라이트의 30%를 묻는 값은 현재 스프라이트(약 1.08 × 0.57) 기준 추정입니다. 실제 구현 시 화면으로 보고 조정해도 되는지.
3. **눌림 연출 강도**: 0.14유닛(0.08초)이 적당한지. 더 크게 가라앉히거나 느리게 할 수 있습니다.
4. **전용 아트**: 눌림 이미지를 따로 만들 계획이 있다면 `pressedSprite`로 연결하는 구조를 그대로 쓰면 됩니다.

답변과 Unity 작업 승인 후 4-2항 → 4-3항 → 5항 순서로 진행합니다.

## 9. 확정 사항과 구현 현황 (2026-10-14)

확정: (1) `P3`·`P5`는 리프트/셔틀 상판에 매립, (2) 매립 깊이·눌림 강도는 구현 후 화면을 보며 조정, (3) 눌림 전용 이미지는 VARCO로 생성해 삽입.

- **스크립트**: `SwitchPressAnimation.cs` 신규, `SwitchTrigger.OnReady` 추가.
- **프리팹**: `P_Trap_Switch_Stage3_Lava`, `P_Trap_Teleport_Stage3_Lava` — 임시 `Visual` 제거, 판형 감지 영역(1.1 × 0.18), `ThemedVisual` 로컬 Y +0.115·sortingOrder -1, `SwitchPressAnimation` 부착(텔레포트는 `TeleportRune`을 `pulseTarget`으로 연결).
- **씬(`Stage3.unity`)**: 스위치 70개(3-1 10, 3-3 50, 3-4 10)를 발판 윗면에 정렬 — 재측정 결과 **전부 간격 0.00**. 3-4 `P3`는 `Mover_3-4_M1`, `P5`는 `Mover_3-4_M3`의 자식으로 상판에 매립. 3-1·3-4 인스턴스에 남아 있던 키 큰 감지 영역 오버라이드 20개를 프리팹 값으로 되돌림.
- **3-4 낙하 포착 텔레포트 5개**: 허공에 스위치 외형이 보이던 `ThemedVisual`/`TeleportRune`을 비활성화(감지 기능은 그대로).
- **검증(플레이 모드)**: 밟으면 눌림(Y 0.115 → -0.025, 색 0.75배) → 쿨다운 3초 뒤 복귀, 발사기 예고 점멸 동작 확인.
- **미완료**: 눌림 전용 이미지(VARCO 생성). 현재는 코드 연출만 적용되어 있으며 `pressedSprite`에 연결하면 바로 쓰인다. `P3`·`P5` 탄도·시점 재검증, 3-4 정상 동선에서 판형 감지 영역이 밟히는지 시뮬레이션 확인도 남아 있다.

## 10. 스위치 이미지 재제작 — 정측면 + 눌림 프레임 (2026-10-14)

기존 `T_Trap_Switch_Stage3_Lava`는 위에서 내려다보는 대각선 시점이라 2D 측면 화면과 맞지 않았다. VARCO(`nano-banana-2`)로 **정측면(윗면이 보이지 않는) 스위치**를 새로 생성했다.

- **생성**: 텍스트 프롬프트로 정측면 용암 스위치 2장 생성 → 완전한 정측면 1장 채택 → 같은 구도로 편집 생성한 "충전"·"발동" 프레임 2장. 편집 모델은 버튼 위치를 내리지 않고 표시등·용암 균열 빛만 바꿨으므로, **빛 변화는 생성 프레임, 버튼이 가라앉는 움직임은 `pressDepth`** 로 나눠 처리한다.
- **후처리**: `@Edit/Process_SwitchFrames.py` — 가장자리와 이어진 흰 배경만 투명 처리, 흰 테두리 잔상 제거, 3장 공통 영역 자르기(발판 윗면 선 바로 위), 1/2 축소(167 × 86).
- **에셋**: `Assets/Sprites/Traps/Themed/SwitchSide_Stage3_Lava/switch_0~2.png` (PPU 167, Point, 피벗 하단 중앙) → 약 1.0 × 0.52 유닛.
- **프리팹 적용**: `ThemedVisual` 스프라이트 `switch_0`, 크기 1, 로컬 Y -0.10(발판 뒤로 살짝 매립). `SwitchPressAnimation.pressFrames = [switch_1, switch_2]`, `pressDepth 0.3`, 눌림 0.12초·복귀 0.25초.
- **`SwitchPressAnimation` 변경**: `pressedSprite`를 `pressFrames` 배열로 교체(눌림 진행도에 따라 프레임 재생, 복귀는 거꾸로 재생).
- **검증(플레이)**: 밟으면 `switch_2`로 바뀌며 발판 속으로 가라앉아 윗부분만 빛나고, 쿨다운 뒤 `switch_0`로 복귀. 이동 발판 위 스위치·텔레포트 룬 연출은 이 단계에서 개별 확인하지 않았다.
- **다른 스테이지**: 1·2·4·5 스테이지용 `T_Trap_Switch_*`는 기존 대각선 이미지 그대로다. 필요하면 같은 방식으로 스테이지별 재생성한다.

## 12. 스위치 형태 재설계 — "저절로 밟히는" 바닥 발판형 (2026-10-14)

10·11항의 스위치는 정측면이긴 하지만 **상자·토템 위에 버튼이 올라간 블록 형태**(높이 0.6 ~ 0.85)라 플레이어가 걸어가다 닿는 장애물처럼 보이고, "지나가면 자연스럽게 밟힌다"는 느낌이 나지 않았다.

- **새 형태**: 발판 윗면에 거의 붙은 **낮고 넓은 판**(폭 대비 높이 약 1/8, 월드 높이 약 0.12 ~ 0.18). 플레이어가 위로 걸어가면 판이 눌리는 모양이며, 상자·기둥·토템·버튼 형태는 금지한다.
- **감지 영역과 일치**: 감지 영역(1.1 × 0.18)이 판 바로 위에 깔려 있으므로 "판 위를 지나가면 작동한다"는 모양과 동작이 맞는다.
- **눌림 연출**: 판이 발판 윗면 높이까지 가라앉고(`pressDepth` ≈ 높이의 60%), 판 가장자리 표시등·룬이 대기 → 충전 → 발동 순으로 밝아진다. 기본 높이가 낮으므로 가라앉으면 발판과 거의 한 면이 된다.
- **수칙 17번 개정**: 정측면 3프레임 한 세트에 더해 "바닥에 붙은 낮은 판 형태(높이 0.2 이하)"를 필수 조건으로 한다.
