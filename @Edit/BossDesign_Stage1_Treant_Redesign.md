작성: OpenAI Codex (GPT-6), 2026-10-14. 상태: **Unity 적용 및 임시 씬 검증 완료(2026-10-14 단차·보스 크기 개정 포함)**.

## 1. 기존 구현과 목표

기존 Stage1 Section_5는 폭 28의 단일 바닥이다. BossController는 수평 추적(2.5/초), 양손 주먹질(전방 2.6, 발밑부터 높이 3, 각 10 피해), 수평 최대 9의 도약 내려찍기(25 피해, 반경 3.6, 발 높이 허용 0.2)를 사용한다. 보스 체력은 100이며 큰 피해 20 또는 누적 30에서 그로기가 발생한다.

2026-10-14 사용자 수정 지시 반영: 보스 이동 바닥을 유지하고 좌우에 얇은 발판을 각각 **정삼각형 5단**으로 배치한다. 아래는 이동 선택지가 많고 위는 적어지는 구조로, 상승·하강 회피와 머리 근접 공격을 선택하게 한다. 좌우는 보스 초기 위치를 기준으로 한 고정 배치이며 보스가 이동할 때 발판은 따라가지 않는다. 보스는 발판에 물리·상호작용하지 않는다. 점프 공격은 **최하단 지면 전체**에 발동하고 플레이어는 발판 위로 올라가 회피한다. 아래 설계가 이전 반경 3.6 충격파 및 비정삼각형 배치를 대체한다.

## 2. 좌표와 발판

로컬 원점은 기존 바닥 중앙 윗면, 월드 (14.78, −49). 바닥 x −14~+14, 두께 1의 연속 발판 하나. Section_5 기존 위치 (14.78, −50)는 유지하고 좌표 변환에 원점의 y 차이 1을 반영한다. 시작 x −11, 보스 시작 x 0, 처치 후 종료 x +12.5. 시작·종료 캐릭터 높이는 실제 발 기준으로 조정한다.

총 30개. 개별 폭 **0.6**, 두께 0.36(바닥과 같은 잔디·흙·돌 단면 슬랩, 512ppu). 좌우 정삼각형의 중심은 x −4/+4이다. 같은 단 높이 오프셋을 없애고, 각 단을 꼭짓점 아래 중앙 정렬한다. 정삼각형은 최하단의 양쪽 끝 발판 중심과 최상단 발판 중심의 3점을 기준으로 정의한다. 발판 자체를 삼각형 모양으로 만들지는 않는다.

단차 h=0.8, 같은 단 중심 간격 s=`2h/√3`≈0.923760, 위층 좌우 이동량 s/2≈0.461880. 밑변 4s≈3.695042, 높이 4h=3.2, 두 빗변도 각각 3.695042이다. 표는 반올림 표시이고 생성 코드는 원래 정밀도를 유지한다. 동일 단 발판 사이 빈 폭은 약 0.32376이며, 서로 분리된 발판은 위층으로 점프해 이동하는 삼각 격자이다. 이 간격 자체가 평지에서 점프를 강제하지는 않는다. 최초 수칙의 직선 발판 통합보다 이번 사용자의 정삼각형 개별 발판 지시를 우선 반영한다. 꼭대기 사이 빈 폭은 7.4(중심 간격 8)로 직접 건너뛰기를 필수 동선으로 삼지 않는다. 반대쪽 이동은 바닥 또는 하강 경로를 사용한다.

상승은 아래에서 통과하고 내려올 때 착지하는 한 방향 발판을 사용한다. 아래 방향+점프 입력 시 현재 지지 발판의 플레이어 충돌만 잠시 해제하고, 플레이어 윗면이 발판 밑면 아래로 내려간 뒤 복구한다(최대 0.35초, 복구 시 겹침 검사). 다른 발판·바닥·다른 플레이어·보스 충돌은 해제하지 않는다. 중첩 콜라이더는 캐시한 목록 전체를 처리한다. 리스폰·비활성화 시 충돌 무시 상태도 복구한다.

외형은 Scale (1,1,1), Tiled/Continuous, size (0.6,0.12), Full Rect 전용 반복 스프라이트. BoxCollider2D는 autoTiling=false, 윗면·폭·두께를 일치시킨다. 신규 반복 발판은 원본 프리팹으로 제작 후 인스턴스 배치한다. 플레이어 몸 폭은 약 0.983으로 발판보다 넓으므로 발판 중앙에서 안정적으로 지지·접지되는지 실제 적용 시 확인한다.

## 3. 점프 성능과 전투 회피

Stage1 씬의 Player 프리팹 GUID는 Player_Warrior를 가리킨다. 해당 파일의 이동 8, 점프 속도 9, 중력 배율 3과 Physics2D 중력 9.81을 기준으로 계산한다. 테스트용 P_MM_Player(점프 14)는 기준으로 쓰지 않는다. 이론 최고 높이는 1.376, 점프 속도 자체를 80%로 줄인 보수적 최고 높이는 0.881이다. **단차 0.8은 두 조건을 동시에 만족하도록 정했다: ① 0.8 ≤ 0.881이므로 바로 아래 단에서 점프하면 한 단 오를 수 있고, ② 2×0.8=1.6 > 1.376이므로 한 번의 점프로 두 단 이상은 오를 수 없다.** 따라서 바닥에서는 1단에만, k단에서는 k+1단에만 오를 수 있고 걸어서 오르는 경로는 없다(0.65는 2단 1.3 < 1.376이라 두 단 점프가 가능해 폐기). 0.8 상승 시 80% 하강 착지 시간 약 0.32초, 수평 이동 가능 약 2.55로 안쪽 상승 경로 중심 차이 약 0.46과 같은 단 이동 중심 차이 약 0.92를 충족한다. Unity 임시 씬에서 100% 점프(속도 9)로 0~3단에서 뛰어도 정점 발 높이가 두 단 위 윗면보다 0.3 낮음을 확인했다.

| 보스 행동 | 플레이어 선택 및 구현 조건 |
|---|---|
| 추적 | 연속 최하단 바닥으로 움직인다. 보스와 상부 발판의 모든 Collider2D 간 물리 충돌·트리거 상호작용을 제외한다. 상부 발판 전용 레이어는 플레이어 groundLayer에만 포함하고 보스 groundLayer에는 제외한다. IsGrounded/HasGroundAt/착지 탐색/공격 대상 쿼리도 발판을 제외하며 최하단 바닥만 지면으로 인정한다. 보스가 발판에 서거나 올라타거나 밀거나 작동시키지 않는다. |
| 주먹질 | 주먹 판정은 몸집(약 2.3배)에 맞춰 전방 4.2·높이 1.4~3.5로 키웠다(발치는 3-3 하단 공격이 담당). 1~3단은 몸·발 위치에 따라 맞을 수 있고 4단(발 3.2)도 높이 3.5 안이라 안전을 보장하지 않는다. 5단 발 높이 4.0은 지상 주먹질 상한 밖이다. 상승 도중에는 판정에 들어가므로 주먹 타이밍을 보고 올라간다. |
| 내려찍기 | 최하단 바닥에 실제 착지하면 x −14~+14 전체에 25 피해 판정이 동시에 발동한다. 피해 띠는 지면 윗면부터 높이 0.25까지, 지속 0.75초. 1단 윗면 0.8부터 모든 발판 위 플레이어는 회피한다. 멀리 달아나거나 벽에 붙어도 지면에 남아 있으면 맞는다. 상세 판정은 아래 3-1절. |
| 그로기 | 머리가 낮아져 저층에서도 보너스를 받기 쉽다. 머리 앵커는 그로기 자세를 따라 내려가며 배율은 최대 2배로 유지한다. 실제 증폭 피해로 기존 그로기 20/30 기준을 판정한다. |

추적·주먹질·그로기는 유지하고 점프 내려찍기만 전역 지면 공격으로 변경한다. 고층은 지상 주먹질과 지면 공격을 피할 수 있으므로 장기 체류가 유리할 수 있다. 신규 상층 공격을 임의로 추가하지 않는다. 적용 테스트에서 상층 대기만으로 공략되는지와 보스가 고층 플레이어를 추적하여 공격 가능한 위치로 이동하는지 평가하고, 필요하면 후속 패턴 설계로 다룬다.

### 3-1. 점프 내려찍기 — 최하단 지면 전체 공격

- 지면은 아레나 바닥의 윗면 로컬 y=0(월드 y=−49)이며 상층 발판은 지면으로 사용하지 않는다. 충돌 레이어 분리와 별개로 지면 참조를 바닥 콜라이더에 연결하여 잘못된 레이어 설정으로 상층을 착지점으로 선택하지 않게 한다.
- 전투 시작 후 첫 공격 4초, 이후 쿨다운 8초. 기존 수평 거리 3 이상 조건을 제거하여 플레이어가 바로 옆이나 발판 위에 있어도 쿨다운이 되면 발동한다. 기존 근접 주먹질보다 특수 공격 우선순위는 유지한다.
- 준비 시작부터 **최소 0.8초** 동안 지면 전체 경고 띠를 표시한다. 준비 0.35초+기존 목표 체공 0.6초를 기준으로 약 0.95초 전에 예고한다. 발판을 향한 수직 도약 목표는 사용하지 않고 플레이어 x만 샘플링하여 최대 9 이내로 도약하며, 바닥 경계와 보스 반폭을 포함해 착지 x를 제한한다.
- 공격 시작 조건은 하강 중 실제 바닥 접촉과 최소 경고 시간 충족이다. 공중에서 시간 제한에 도달했다는 이유로 충격파를 발동하지 않는다. 실제 바닥 착지 실패 시 공격을 취소하고 복구 상태로 전환한다. 준비·도약 중 그로기 또는 사망으로 취소되면 경고도 제거한다.
- 착지 x나 기존 반경 3.6에 관계없이 **바닥 전체 폭 28**에서 동시에 발동한다. 지면 공격은 별도 `BossArenaGroundSlam` 역할로 설계하고 BossController는 시작/취소만 전달한다. 피해 기준은 플레이어 몸 콜라이더의 **발 높이(bounds.min.y)**이며 몸 중앙이 아니다. 아레나 x 범위와 몸 수평 범위가 겹치고 발이 지면+0.25 이하일 때 피해 대상이다. 실제 바닥 아래로 낙하한 대상은 전용 낙사 판정에 맡긴다.
- 0.75초 활성 동안 고정 물리 갱신마다 캐시한 플레이어를 검사한다. 각 플레이어는 이번 공격에 최대 1회 25 피해만 받는다. 발판에서 내려와 활성 지면에 착지하면 피해를 받는다. 발판 위에서는 몸이나 검이 경고 띠와 겹쳐도 발 높이가 안전 범위이므로 피해를 받지 않는다.
- 1단 발 높이 0.8은 위험 상한 0.25보다 0.55 높다. 일반 점프의 총 체공 시간은 약 0.612초로 공격 활성 0.75초보다 짧으므로 **바닥에서 제자리 점프 한 번만으로 전체 활성 시간을 버틸 수 없다**. 짧은 공중 이동 자체를 피해로 처리하지 않으며, 경고 시간 안에 발판에 올라가 공격 종료까지 머무르는 것을 기본 회피법으로 한다.
- 지면 충격파의 표현·피해 시스템은 발판을 공격하거나 발판 상호작용을 작동시키지 않는다. 이미 활성화한 충격파는 보스 사망·영역 이탈·씬 종료 시 즉시 정리한다.

### 3-2. 보스 크기와 머리 타격 높이 (2026-10-14 사용자 수정)

기존 보스는 전체 높이 약 3.05(머리 중심 약 2.3)로 최상층 발판(윗면 3.25)보다 작아 5단에 올라가면 머리를 내려다보았다. 게임 방식에 맞게 **최상단(5단)에서 서서 검을 휘두를 때만 머리에 닿는 크기**로 바꾼다.

- 플레이어 검 판정: 발 기준 중심 높이 0.643(AttackPoint y 4.94×0.130208), 반경 0.75 → 서서 닿는 최고 높이 = 단 윗면 + 1.393. 4단 도달 4.593, 5단 도달 5.393.
- 머리 판정 하단 = **4.95**(4단 도달 4.593 < 4.95 < 5단 도달 5.393, 여유 각각 0.36/0.44). 보스 형상 높이 **7.0**(스프라이트 10.16 → Visual 배율 0.689, 기존 0.3의 약 2.3배). 얼굴 중심은 약 5.2, 머리 앵커는 애니메이션별 실제 머리 픽셀 위치를 그대로 따른다.
- 몸통 판정(루트 BoxCollider2D): 폭 2.4 × 높이 4.95(지면~머리 하단). 전 단에서 타격 가능하다. **머리 판정(`HeadHurtbox`, Visual 자식 트리거)**: 월드 x −0.4~1.5(바라보는 방향 기준), y 4.95~7.0. 방향 반전을 따라가며 같은 Rigidbody이므로 한 번의 검 공격은 단일 피해로 처리된다.
- 이동·공격 보정: stopDistance 2.2, meleeRange 4, punchReach 4.2, punchHeight 3.5, landingStandoff 3, edgeProbe 1.5. 카메라 크기는 5 → 6.5(보스 머리 7.0과 5단 플레이어가 함께 보이도록. 구간 높이 16.9 이내).
- 한계: 서서 휘두르는 기준이다. 4단에서 점프 정점(발 +1.376) 근처로 휘두르면 5.97까지 닿아 머리에 닿을 수 있으며, 이 점프 공격은 막지 않는다. 그로기 때 머리 앵커는 낮아지지만 머리 판정 상자는 고정이라 저층에서 닿는 것은 몸통 판정이다(배율은 앵커 거리로 계산).
- 검증(임시 Test777 씬, 완료 후 삭제): 단별 검 도달 — 1~5단 모두 몸통 명중, 머리는 5단만 명중. 76개 항목 전부 통과.

### 3-3. 하단 공격 — 뿌리 쓸기 (2026-10-14 추가)

보스가 약 2.3배 커져 플레이어가 보스 발치(바닥·1단)에 있는 경우가 많아졌다. 기존 주먹은 가슴~머리 높이로 뻗어 발치의 플레이어 머리 위로 지나가므로, 발치를 맡는 하단 공격을 추가한다.

| 항목 | 값 |

## 4. 머리 근접 대미지

머리의 현재 월드 위치와 **타격 시점 플레이어 몸 콜라이더 중심**의 2D 거리 d를 사용한다. 발판 단수·공격 판정 중심·투사체 위치로 대신 계산하지 않는다. 이미 성공한 공격의 피해만 증폭하며 머리에 가까워졌다는 이유로 자동 공격하거나 공격 사거리를 늘리지 않는다.

`t = clamp01((4.0 - d) / (4.0 - 0.75))`

`multiplier = 1 + t` / `finalDamage = max(1, floor(baseDamage * multiplier + 0.5))`

| 거리 d | 배율 | 기본 피해 10의 결과 |
|---:|---:|---:|
| 4 이상 | 1.00 | 10 |
| 3 | 1.31 | 13 |
| 2 | 1.62 | 16 |
| 1 | 1.92 | 19 |
| 0.75 이하 | 2.00 | 20 |

baseDamage가 0 이하이면 0 피해. 보스가 죽었으면 무시. 최대 배율 2, 시작 반경 4, 최대 배율 반경 0.75는 초기 조정값이다. 머리 앵커/공격자 정보가 없거나 공격자가 비활성·파괴되면 기본 피해만 적용한다. 투사체는 발사자 콜라이더 참조를 보유하고 명중 시점 위치를 샘플링한다. 멀리서 발사한 뒤 머리 쪽으로 접근하면 명중 시점 거리를 반영한다.

보스 Visual 아래 HeadAnchor를 둔다. 기본 위치는 Visual 로컬(1.08, 7.56)이며 Visual 배율 0.689 적용 시 바닥 기준 약 5.2(실제 머리 픽셀 중심). 방향 반전·걷기·도약·공격·그로기마다 애니메이션에 머리 위치 트랙을 추가한다. 단순히 몸 콜라이더 상단(4.95)이나 전체 스프라이트 상단을 쓰면 실제 머리와 어긋나므로 앵커로 구분한다. HeadAnchor에는 새 피격 콜라이더를 추가하지 않아 기존 검 판정·중복 피격을 늘리지 않는다.

## 5. 구현 연결 설계

기존 IDamageable.TakeDamage(int)는 공격자 정보를 받지 않는다. 전역 GameManager 플레이어를 무조건 대입하면 환경 피해도 증폭될 수 있으므로 피해 문맥을 전달하는 선택적 인터페이스를 설계한다.

```csharp
// 설계 의사코드: 실제 Assets 코드로 등록되지 않았다.
// 작성 OpenAI Codex (GPT-6), 2026-10-14.
public struct DamageContext {
    public int baseDamage;
    public Collider2D attackerBody; // 투사체이면 발사한 플레이어의 몸
}
public interface IContextDamageable {
    void TakeDamage(DamageContext context);
}
// 이미 타격에 성공한 대상에 대해 호출하는 공통 피해 전달 함수.
// 문맥을 지원하는 보스만 새 경로를 사용하고 나머지는 기존 경로를 따른다.
void Deliver(IDamageable target, DamageContext context) {
    if (target is IContextDamageable receiver) receiver.TakeDamage(context);
    else target.TakeDamage(context.baseDamage);
}
// 머리 거리 증폭 컴포넌트가 계산만 하고 Boss가 체력/이벤트를 담당한다.
// Boss.TakeDamage(context)는 증폭 결과를 기존 TakeDamage(int)에 한 번 전달한다.
// TakeDamage(int)를 직접 호출하는 환경 피해에는 추가 배율을 적용하지 않는다.
```

향후 코드 역할: `BossHeadProximityDamage`는 거리와 배율 계산, `Boss`는 체력과 이벤트, `PlayerCombat`/`Projectile`은 문맥 전달, `PlayerPlatformDrop`은 하강 입력과 해당 접촉 충돌 복구. 신규 실제 스크립트는 Assets/@Scripts 하위. 보스 프리팹에 컴포넌트를 붙이는 것으로 대상 범위를 1-5에 한정한다.

PlayerCombat의 현재 타격 반복문은 콜라이더마다 피해를 전달하므로 하나의 Rigidbody2D에 여러 콜라이더가 생기면 중복된다. 공격 한 번마다 캐시 버퍼에서 대상 Rigidbody2D를 중복 제거한 뒤 Deliver를 한 번 호출한다. 증폭은 전달 직전 한 번만 계산하며 Boss.OnDamaged는 실제 HP 차감량을 전달한다. 증폭 배율 표시는 별도 이벤트로 UI에 보내 체력 부족으로 잘린 피해와 배율을 혼동하지 않는다.
