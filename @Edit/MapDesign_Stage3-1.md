# Stage3 - Section_1(3-1) 맵 설계안 (재설계, v2)

> **이 문서는 이전 버전(동선 길이 75, 수직 리프트 설계)을 대체합니다.** Unity 씬 작업은 진행하지 않았습니다(설계안만 작성). 아래 좌표/수치를 검토 후 승인하시면, 별도 요청 시 Unity에서 실제 배치 작업을 진행합니다(LHS_Custumer.md 규칙 9, 11 / MapEdit.md 규칙 1).

## 1. 요청 사항 정리 (이번 지시 원문 기준)

1. 플레이어의 이동 동선은 **절대 직선 배치 금지**.
2. 플레이어의 동선 길이는 **정확히 60**.
3. 플레이어가 스위치 오브젝트와 접촉하면 원거리 투사체를 발사하는 함정을 **5개 이상** 배치.
4. 발판은 **일반 15개 + 데미지 5개 + 이동형 3개**(총 23개), **같은 종류의 발판을 연속 배치 금지**.
5. 발판 간격은 플레이어가 **점프+대쉬 조합으로 반드시 건널 수 있는 간격**이어야 함.

## 2. 플레이어 이동 스펙 확인 결과

- `Player_Warrior.prefab` (`PlayerMovement`): moveSpeed=8, jumpForce=9, gravityScale=3 → 유효 중력 ≈29.43.
  - 최고 점프 높이 ≈ **1.38유닛**, 동일 높이 착지 기준 최대 수평 점프거리 ≈ **4.9유닛** (기존 설계들과 동일 공식).
- `PlayerDash.cs` (신규 확인): `dashDistance=0.9`, `dashDuration=0.2s`, `dashCooldown=0.8s`. 대쉬 중에는 수직 속도를 0으로 고정하고 수평 속도만 `dashDistance/dashDuration`로 고정 이동 — **순수 수평 이동 0.9유닛**짜리 보조 수단입니다(쿨다운 0.8초).
- **점프+대쉬 조합 최대 수평거리(실전 설계용 근사치)**: 점프 단독 최대(4.9) + 대쉬 거리(0.9) ≈ **5.8유닛**. 이 프로젝트의 기존 설계 문서들과 동일한 수준의 단순화된 근사 공식이며, 엄밀한 탄도 재계산이 아닌 "점프만으로는 절대 못 건너고, 점프 도중 대쉬를 섞어야 건널 수 있는 구간"을 설계하기 위한 기준값입니다.
- 따라서 이번 설계에서 **"점프+대쉬 조합이 반드시 필요한 간격"은 수평거리(dx) 5.0~5.3유닛대**로 잡았습니다(4.9 초과 = 점프 단독 불가, 5.8 이하 = 대쉬 병행 시 가능).

## 3. 규칙 4 수치 검증과 불가피한 충돌 — 그리고 해결 방법 (중요, 확인 필요)

"일반 15 + 데미지 5 + 이동형 3 = 23개"를 하나의 순차 경로(★→...→○)로 배치하면서 "같은 종류 연속 배치 금지"를 지키려 하면, **수학적으로 불가능**합니다.

- 23개 중 일반 발판이 15개로 전체의 65%를 차지합니다.
- 발판을 일렬로 나열할 때 특정 종류가 연속되지 않게 배치 가능한 조건은 "그 종류의 개수 ≤ ⌈전체 개수/2⌉" 입니다. 23개 기준 ⌈23/2⌉=12 인데 일반 발판은 15개 → **최소 (2×15-23-1)=6쌍은 반드시 일반-일반이 연속**하게 됩니다.

이를 그대로 보고만 드리기보다, **기존에 구현되어 있는 "소멸형(사라지는) 발판"을 구분자로 6개 추가**해서 문제를 해결했습니다.

- 전체 발판 수를 23개 → **29개**(일반15 + 데미지5 + 이동형3 + 소멸형6)로 늘리면, 전체 29개 중 가장 많은 종류(일반 15개)가 정확히 ⌈29/2⌉=15 가 되어 **"종류-구분자-종류-구분자..." 형태로 완벽하게 교차 배치가 가능**해집니다(연속 배치 0건).
- 즉 **홀수 번째(1,3,5,...,29번째, 총 15개) = 전부 일반 발판**, **짝수 번째(2,4,...,28번째, 총 14개) = 데미지5+이동형3+소멸형6**을 자유 순서로 배치 → 어떤 발판도 같은 종류끼리 이웃하지 않습니다.
- 요청하신 "일반15/데미지5/이동형3"의 개수는 정확히 그대로 유지되며, 소멸형 6개는 규칙 4의 "연속 배치 금지"를 만족시키기 위해 **추가로 삽입한 구분자**입니다(지난 75-길이 설계에서도 "부족분을 소멸형으로 보충"한 전례가 있어 동일한 방식을 재사용했습니다).

**→ 승인 전 확인 필요**: 이 소멸형 6개 추가가 의도와 다르다면, (a) 일반 발판 개수를 줄이거나 (b) 연속 배치를 일부 허용하는 방향으로 재설계할 수 있습니다. 아래 설계는 위 해결 방법(소멸형 6개 추가)을 적용한 버전입니다.

## 4. 전체 구조 요약

- 좌표 기준: 시작 지점(★)을 (X=0, Y=0)으로 삼은 상대 좌표.
- 총 29개 노드, 28개 구간(점프). **모든 구간이 dx≠0 그리고 dy≠0인 대각선 이동**이며, 수평 평지(dy=0)나 수직 직선(dx=0) 구간은 단 하나도 없습니다(규칙 1 "절대 직선 금지" 충족).
- 좌우로 번갈아(zigzag) 이동하며 꾸준히 상승(dy는 전 구간 양수)하는 구조.

## 9. 발판 간격 검증 (요청: 점프+대쉬 조합으로 반드시 건널 수 있는 간격)

- **표준 구간(24개 + 보정 1개, dx=1.5~1.881)**: 점프 단독 최대 수평거리(4.9) 대비 충분히 작아 **점프만으로도 항상 안전하게 통과 가능**.
- **대쉬 필수 구간(3개, dx=5.2)**: 점프 단독 최대(4.9)를 **초과**하여 점프만으로는 절대 건널 수 없고, 점프 중 대쉬(+ 0.9)를 병행해야 하는 **점프+대쉬 조합 필수 구간**으로 설계했습니다. 조합 시 근사 최대치(5.8) 이내이므로 **항상 건널 수 있음**이 보장됩니다.
- 대쉬 쿨다운(0.8초)은 세 대쉬 구간 사이에 표준 구간 7~8개(각각 걷기+점프 포함, 수 초 소요)가 끼어 있어 **쿨다운 때문에 막히는 구간은 없습니다**.

## 10. 비고 / 확인 필요 사항

1. **(중요, 3번 항목 참고)** 소멸형 발판 6개를 "연속 배치 금지" 규칙을 만족시키기 위해 추가했습니다 — 요청하신 "일반15+데미지5+이동형3=23개" 자체만으로는 수학적으로 연속 배치를 완전히 피할 수 없기 때문입니다. 이 추가가 괜찮은지 확인 부탁드립니다.
2. **(중요)** 스위치→투사체 함정 기능은 현재 설계 문서로만 존재하고 실제 스크립트가 없습니다. Unity에 배치하려면 `SwitchTrigger.cs`/`ProjectileLauncher.cs`/`ZoneEventTrigger.cs` 구현이 선행되어야 합니다.
3. 이동형 발판(Lift_1~3)은 이번 설계에서는 수직 왕복 거리가 크지 않은(탑승 지점 주변을 좁게 왕복하는) "불안정한 발판" 컨셉으로 사용했습니다 — 큰 구간은 대쉬로 건너고, 이동형 발판은 "흔들리는 발판 위에 착지"하는 타이밍 챌린지 역할입니다. 왕복 폭/속도는 설계 문서에 수치를 명시하지 않았으므로, 실제 배치 시 `MovingPlatform.speed`(기본 2) 및 `PlatformPath` 경로 폭을 별도로 정해야 합니다.
4. 전체 폭은 약 14.5유닛, 높이는 약 25.6유닛입니다. `CameraBoundsZone`이 이 범위를 커버하는지는 실제 배치 시 확인이 필요합니다.
5. 본 설계는 **코드(문서) 설계만 완료된 상태**이며, Unity 씬 적용은 요청하지 않으셨으므로 진행하지 않았습니다(MapEdit.md 규칙 1).
