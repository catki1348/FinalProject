# Stage3 - Section_1(3-1) 맵 설계안

> Unity 씬 작업은 진행하지 않았습니다(설계안만 작성). 아래 좌표/수치를 검토 후 승인하시면, 별도 요청 시 Unity에서 실제 배치 작업을 진행합니다(LHS_Custumer.md 규칙 9, 11 / MapEdit.md 규칙 1).

## 1. 요청 사항 정리

- 컨셉 이미지 없이 3스테이지(용암 동굴 테마)의 첫 영역(3-1)을 신규 설계.
- **동선 길이(★→○ 실제 이동 거리) = 정확히 75**로 설정.
- 직선(수평 평지) 이동을 최소화하고, **상하 이동 + 대각선 이동 위주**로 구성.
- 발판 구성: **일반 10개 + 데미지 10개 + 이동형 3개**, 그래도 부족한 부분은 **소멸형(사라지는 발판)**으로 보충.

이 조건에 맞춰 "용암 수직 갱도를 지그재그로 오르는 구조"로 설계했습니다 — 좌우로 번갈아 뛰며 계속 상승하고(대각선 위주), 3개의 이동형 발판(용암 승강 리프트)이 한 번에 점프로 오를 수 없는 큰 구간을 이어줍니다.

## 2. 기존 씬 데이터 확인 결과 (Stage3.unity)

- `Section_1`은 현재 placeholder 상태(실제 폭 약 2유닛, 지형 없음) — `MapDesign_AllStages_Layout.md`의 임시 간격 기준으로만 위치가 잡혀 있습니다.
- 이번 설계는 **수평 폭은 약 7유닛으로 좁고, 수직 높이가 약 41유닛으로 매우 긴 형태**입니다(요청하신 "상하 이동 위주"의 자연스러운 결과). 실제 배치 시 `CameraBoundsZone`이 이 정도 세로 폭을 커버하는지 별도 확인이 필요합니다(6번 비고).
- 플레이어 이동 스펙(`Player_Warrior.prefab`: moveSpeed=8, jumpForce=9, gravityScale=3): 최고 점프 높이 ≈ **1.38유닛**, 최대 수평 점프거리 ≈ **4.9유닛**. 아래 모든 도보 점프는 dy=1.2(한계의 87%), dx=2.5(한계의 51%)로, 상승감은 강하게 유지하면서도 안전 마진을 남겼습니다.
- 인터랙티브 발판 스펙(`@Edit/PlatformDesign_InteractiveFootholds.md`, 구현 완료 상태 기준):
  - **데미지형**(`DamageFoothold`): 0.5초 머물러야 피해 시작, 이후 0.5초 간격 반복 8데미지. → 착지 직후 바로 다음으로 도약하면(0.5초 이내) **무피해 통과 가능** — "위험하지만 숙련되면 안전한" 긴장 구간으로 활용.
  - **소멸형**(`DisappearingFoothold`): 밟은 뒤 0.4초 후 사라지고, 2초 후 재생성.
  - **이동형**(`MovingPlatform`+`PlatformPath`, `PingPong`): 왕복 이동 발판, 도보로는 불가능한 큰 수직 구간(6유닛)을 이어주는 용도로 사용.

## 3. 좌표 기준 및 전체 구조

이하 모든 좌표는 **시작 지점(★)을 (X=0, Y=0)으로 삼은 상대 좌표**입니다. 좌우로 번갈아(dx=±2.5) 상승(dy=+1.2)하는 지그재그 4구간(Phase A~D)을, 3개의 수직 리프트(이동형)가 이어주는 구조입니다.

```
Y(고도, 용암 갱도를 위로 오름)
40.8 ┤                                  ○(골인)
     ┤                              ╱
30.8 ┤        (Phase C: 지그재그)  ╱
     ┤       ┆ (리프트3, +6.0)   ╱
24.8 ┤        (Phase B: 지그재그)
     ┤       ┆ (리프트2, +6.0)
18.4 ┤        (Phase B 계속)
     ┤       ┆ (리프트1, +6.0)
 6.0 ┤        (Phase A: 지그재그)
 0.0 ┤★
     └──────────────────────────────────
      X: 0 부근에서 좌우로 ±2.5 진동
```

## 6. 동선 길이 계산 (요청 사항: 정확히 75)

| 구간 | 개수 | 개당 거리 | 소계 |
|---|---|---|---|
| 표준 대각 점프(dx=2.5, dy=1.2) | 17개 | 2.7731 | 47.1427 |
| 리프트 탑승/하차 소점프×3, 수직 이동×3 | 3세트 | 8.0396 | 24.1188 |
| 최종 골인 점프(dx=3.54, dy=1.2, 총량 보정용) | 1개 | 3.7385 | 3.7385 |
| **합계** | | | **≈ 75.000** |

**→ 이동 동선 길이 = 75 (요청값 정확히 달성)**

모든 개별 점프(표준 2.7731, 소점프 1.0198, 최종 3.7385)가 플레이어 최대 수평거리(4.9)·최대 상승고도(1.38) 이내로 전부 안전하게 클리어 가능합니다. 순수 수평 이동(평지 도보) 구간은 설계에 포함하지 않았고, 모든 전환이 대각선 또는 수직(리프트) 이동입니다 — 요청하신 "직선 최소화, 상하·대각선 위주"를 그대로 반영했습니다.

## 7. 비고 / 확인 필요 사항

1. 수직 높이가 약 41유닛으로 매우 큽니다. 카메라가 이 구간 전체를 어떻게 보여줄지(세로로 긴 `CameraBoundsZone`, 또는 등반 중 카메라가 위로 스크롤)는 `@Edit/CameraDesign_FollowCamera.md` 쪽 설계와 맞춰 확인이 필요합니다.
2. 데미지형 발판은 "0.5초 내 이탈하면 무피해" 특성상 손이 빠른 플레이어는 사실상 안전하게 통과할 수 있습니다. 난이도를 더 올리고 싶다면 `damageDelay`를 낮추는 방안을 검토할 수 있습니다(스크립트 파라미터 조정, 별도 승인 필요).
3. 리프트(이동형) 3개는 모두 동일하게 "탑승 지점 → 수직 6유닛 상승 → 하차 지점" 구조의 `PingPong` 왕복으로 설계했습니다. 왕복 주기(속도)는 설계 문서에 명시하지 않았으므로, 실제 배치 시 `MovingPlatform.speed` 값(기본 2)을 그대로 쓸지 별도로 정할지 확인이 필요합니다.
4. 좌표/폭/발판 배치는 설계 제안이며, 실제 배치는 Unity 작업이므로 사용자 승인 후 별도로 진행합니다(규칙 9, 11).
