---
description: 현재 진행 중인 작업을 요약해 HANDOFF.md에 저장 (다른 PC에서 이어서 작업하기 위함)
---

지금까지의 대화와 작업 내용을 바탕으로, 다른 PC에서 이 세션 없이도 작업을 이어갈 수 있도록
프로젝트 루트의 `HANDOFF.md` 파일을 새로 작성(덮어쓰기)하라.

파일에는 다음 항목을 포함할 것:

1. **작성 시각** (예: 2026-09-16 14:30)
2. **현재 목표** — 지금 무엇을 하려고 하는지 한두 문장
3. **진행 상황** — 지금까지 완료한 것 (완료된 파일/기능 위주로, 불릿 리스트)
4. **다음 할 일** — 이어서 해야 할 작업 (구체적인 순서가 있으면 순서대로, 불릿 리스트)
5. **중요 결정/맥락** — 왜 이렇게 하기로 했는지, 시행착오, 주의할 점 (있는 경우만)
6. **관련 파일 경로** — 이번 작업과 관련된 주요 파일/디렉터리 목록
7. **커밋 상태** — 이 절차가 끝나면 아래 8번에서 자동으로 전부 커밋되므로, 원칙적으로 "커밋 안 된 변경 없음" 상태가 된다. 혹시 커밋 대상에서 의도적으로 제외해야 할 이유가 있는 변경(예: 깨진 상태의 실험적 코드)이 있다면 여기에 적어두고, 8번 커밋 전에 그 파일만 `git add`에서 제외한다.

간결하게 작성하되, 다른 PC에서 이 파일만 읽고 새 세션을 시작해도 맥락을 파악할 수 있을 정도로 충분히 구체적으로 쓸 것.
기존 `HANDOFF.md`가 있다면 내용을 덮어써서 최신 상태로 갱신한다.

8. **자동 커밋** — HANDOFF.md 작성이 끝나면, 다른 PC에서 그대로 이어받을 수 있도록 이 시점의 작업 트리 전체를 자동으로 커밋한다.
   - `git status`로 현재 변경 목록을 확인한다.
   - 7번에서 제외하기로 한 파일이 없다면 `git add -A`로 전부 스테이징한다(제외할 파일이 있다면 그 파일만 빼고 나머지를 스테이징).
   - 아래 형식의 커밋 메시지로 커밋한다(다른 커밋 메시지 스타일을 흉내 내지 말고 이 형식을 그대로 사용):
     ```
     자동 핸드오프 커밋 (사용량 임계치 도달)

     Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
     ```
   - git push는 하지 않는다(사용자가 원할 때 직접 push).
   - 커밋에 실패하면(예: 커밋할 변경사항이 없음) 실패 사실과 이유를 그대로 기록해두고 진행을 멈추지 않는다.

작성/커밋이 끝나면 HANDOFF.md 경로와 생성된 커밋 해시(또는 커밋할 변경사항이 없었다는 사실)를 알려줘라.
